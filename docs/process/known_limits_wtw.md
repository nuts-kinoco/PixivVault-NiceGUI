## R3 最終再検証の既知の限界（2026-11-20）

- **Windows の通知は API 呼出直前まで照合する。** 所有者の確認値を取得してロックを解放したあと、`win11toast.toast()` に入る直前にスレッドが中断すると、切替後に旧所有者の保存件数が通知される可能性がある。偽の送信関数を使った2万回で、最終照合から関数入口までの中央値は1.0 µs、95パーセンタイルは2.4 µs、観測最大は19.7 µs。時間の上限は保証できず、Windows 内部の配信待ちと表示済み通知の取消は未計測。ケースによって旧件数が見えるか、一度限りの通知が抑止される。別アカウントへの書き込み、取得停止ゲートの迂回、保存データ・受領証・履歴の喪失に至る経路はこの区間にない。 [隔離計測](../../../tmp/r3int-20261120/18-toast-interval.json)
- **すでに紐づいた空台帳は再割当てしない。** 台帳の履歴0件から、過去の誤紐づけと正当な初回紐づけを判定できない。間違った既存紐づけがある環境では別の所有者の定期チェックが拒否される。台帳・☆・保留を保持する。今回以降の初回紐づけは切替と直列化した。
