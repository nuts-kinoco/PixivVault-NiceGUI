# AGY 運用メモ（PV、2026-11-19。EMA 監督の実績を参考に採用。性能差は仮説を含む）

## 呼び出し
`agy -p "<依頼文>" --mode plan --dangerously-skip-permissions --model gemini-4-neon-high > out.md 2> err.txt`
- Bash の run_in_background で実行し、完了通知を待つ。開始・終了の時刻を残す。
- モデル id は `agy models` で確認（gemini-4-neon-{low..xhigh}、gemini-4-argon-{low..high}、gemini-3.8-flash-{low..high}）。
- `--sandbox` は付けない（ファイルが見えなくなる）。@ にはファイルの絶対パスを書く。low は使わない（ファイルを読まずに捏造した例がある）。
- cwd は読取専用の対象ツリーにし、実行の前後で `git status` を照合する。
- 初回の「empty conversation id」は会話が始まっていない失敗。短い疎通確認の後、1 回だけ再実行してよい（重複送信ではない）。
- 5 時間枠が切れると high・medium がタイムアウトする。広い問いの Argon は 900 秒でタイムアウトした例がある。

## 依頼文の形（絞るほど速く正確）
1. 冒頭に「読取専用。ファイルは変更しない。git diff A..B を実際に読み、根拠を示す」と書く。
2. 重点の観点を番号付きで 3〜5 個に絞る。
3. 出力形式を指定する: 重大度（重大/高/中/低）・file:line・再現条件・根拠。推測は推測と明記させ、指摘なしの項目も「問題なし」と根拠を 1 行で書かせる。

## 使い分け
- Neon high: 難しい監査・独立意見の第一候補（Gemini 枠で安い）。広い依頼では重大度を過大に付けがちなので、問いを絞る。
- Argon high: 設計の網羅性・順序の監査。Neon の次の手。
- Sol: 実装と修正を伴う検証。Neon の指摘は未検証の入力として Sol に渡し、各指摘の真偽をコードで確かめさせ、採否と根拠を返させる。
- Flash High: 軽作業に限る（証拠の存在確認と要約、受入記録との突き合わせ、失敗ログの一次仕分け）。判断には使わず、出力は原本で確かめる。
