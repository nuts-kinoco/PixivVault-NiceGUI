# P3 の知見（2026-11-20）

P3（機能の完成）を通して得た運用上・技術上の知見。事実と仮説を分けて書く。評価の数値は `ops/LESSONS_wtw_Z10_20261119.md` の評価欄に追記する。

## 1. 進め方（事実）
- **同じ欠陥の型が 2 ラウンド続いたら、修正を重ねず設計を変える。** wt-w のアカウント分離は 10 ラウンド同じ型（アカウントの受け渡し漏れ）が経路を変えて再発した。Argon・Neon・Astra の設計助言（取得結果に所有者を型で束縛、書き込み出口が所有者を必須引数で検証）に切り替えて、High が 3 → 0 になった。`ops/convergence_check.py` と `ops/DEFECT_CLASS_LEDGER.md` で機械的に判定する。
- **契約試験の列挙範囲が、検証の漏れの範囲を決める。** 反射列挙が 5 クラスだけだったため、実行中の操作・ブックマーク再開・待機あり集計が範囲外になり、第 11 回に High が出た。列挙の対象を広げ、未分類のメソッドがあれば失敗する形にしてから収束した。
- **「0 件でも取得元を持つ」ように型で束縛する。** 所有者の情報を引数の約束で渡すと、省略可能な引数の既定値が静かに素通りする。
- **受入の線を最初に置く。** 「High 0」を線にし、Medium は既知の限界として記録して統合する運用が、収束を速めた。ただし原受入の中核（通知・☆編集など）に関わる Medium は直す。
- **性能の閾値は設計の副産物として測る。** 閾値の追求で停滞していないかをユーザーに確認され、「私が決めた目安で、原受入ではない」と分けて説明した。閾値は依頼文に根拠付きで書く。

## 2. 実機との乖離（事実）
- **試験は空の保存先から始めるため、旧版が作った既存の利用者データを開く経路が未検証だった。** 世代索引が未作成の実機の保存先で `active generation index missing` となり起動できなかった（独立検証 13 ラウンドと全体試験 3,649 件では検出されず）。COS に渡す前に、監督が実機プロファイルの複製（退避後）で起動確認したことで見つかった。型を REAL-LAYOUT として台帳に記録した。
- **対策**: (1) 旧版で作った保存先の並びのフィクスチャ、(2) 保存先を共有する全台帳を初期化してから開く結合試験、(3) COS 前の実機プロファイル複製での起動確認。
- 旧版の中断跡（保存・隔離・索引準備の途中停止）が残る保存先は、安全側に起動を拒否する（既知の限界）。

## 3. 独立検証の使い分け（事実）
- Sol のレビューは、OpenAI の安全フィルタで失敗することがある（「攻撃」「改変」「リンク」などの語）。依頼文は「通常の使い方での品質確認」「本人のファイルを外部の道具で書き換える操作は対象外」のように書き、再依頼は 1 回だけ。
- Neon high（Gemini 枠）は、問いを 3〜5 個に絞ると速く精度が高い。広い依頼では重大度を過大に付けがち。指摘は未検証の入力として Sol に真偽を確定させる（実例: E01 の「設定の混入」は、元と同じ全 DB バックアップで復元に必要と確定し不採用）。
- **Claude 側の読み取り専用レビュー（Opus サブエージェント 3 本、各 2〜3 分）が、Codex の検証が見ない観点を拾った。** 例: P5 が見出しの明朝（Yu Mincho）を撤去していた（元の見た目契約違反）、衝突解消で試験の時間条件が厳しい値に戻っていた。**「元が正」の原資料（元の gui.py・憲法文書）との照合は、実装者・Codex の検証とは別の担当に渡すと効く。**
- 低リスクの表示差分でも、元のコードで裏付ける（元の Flet Web 画面の比較だけでは、デスクトップ版の挙動と違うことがある）。

## 4. 待ち方と応答性（事実）
- Codex の完了を前景の `sleep` ループで待つと、その間ユーザーや他セッションのメッセージが読まれない（11-19 は約 72 回・合計約 8.9 時間）。ジョブは `run_in_background: true` で実行し、完了通知を受け取る。待つ間に別の作業と応答をする。
- 再起動などで中断したジョブは、receipt が running のままになる。events.jsonl の更新時刻とプロセスで生存確認し、同じ thread で `--resume` する。

## 5. 公開リポジトリへの push（事実）
- GitHub の main と共通祖先のない別系統の履歴は、別ブランチ（`pv-dev-baseline`）として push する。push 前に、機密パターン（Git 履歴 176 件の候補）を原本で確認し、すべて試験の合成値か、公開済みの公式アプリ定数だった（`evidence_secret_triage_20261120.md`）。作者欄のメールが公開されることは、本人に選択肢で確認した。

## 6. 仮説（未検証）
- 設計の再検討を、2 ラウンド目ではなく最初の再発で行えば、wt-w の所要は半分になった可能性がある。
