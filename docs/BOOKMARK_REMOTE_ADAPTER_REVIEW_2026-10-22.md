# 段階4｜マイブックマーク実データの読取境界

対象は `bookmark_remote_adapter.py` と `test_bookmark_remote_adapter.py`。これは実API接続前の**純粋な変換・4経路集約**であり、Pixivへ接続せず、Cookie・本番DB・保存画像・Git以外の情報を扱わない。従来の合成UIを既定のまま保持する。

## 原版との照合

- 原版 `pixiv_client.py` の `get_bookmarked_works` と `get_bookmarked_novels` はそれぞれ公開 `show` と非公開 `hide` を48件単位で列挙する。四経路が**最後まで完走**しなければ、更新可能なスナップショットとはみなさない。途中取得できた件数を部分成功としてキャッシュへ反映しない。
- 原版 `library_tab.py:255–295` はサムネイルURLなしの項目を一覧から除外し、取得成功時のみリモートキャッシュを全置換する。`ok`のコメント中には「どれか1経路成功」と書かれているが、実コードの最終行は `ok=all_succeeded[0]` であり、ここでは後者を契約とする。
- 原版で失われやすい作品の種別、公開区分、作者ID、タグ、作成日、ページ数、サムネイルURLを `RemoteBookmark` の独立フィールドで保持する。原版では作品/小説間の数値IDが衝突し得るため、NiceGUI用の作品IDは小説だけ `novel:<id>` と区別する。
- 未DL作品をローカル `works` 表へ書き込むことはしない。既存 `BookmarkState` へ反映する際も、四経路成功なら `ok=True`、一部でも失敗なら `ok=False` を渡し、旧キャッシュを保持する。

## 今回のコードの範囲

モジュール自体はHTTPクライアントを生成せず、資格情報取得・画像プロキシを行わない。ただし、**注入したクライアントの取得メソッドを呼ぶため、実PixivClientを渡せば外部GETは発生する**。今回のテストでは必ず合成クライアントを渡し、アプリの既定UI/サービスからは未接続にする。サムネイルURLは `https://i.pximg.net/` の形だけ許可し、ホスト/スキーム・制御文字/不正な空白、作品ID/ページ数/タグ/作品種別/閲覧制限の不正な値は**スナップショット全体を失敗**にして既存キャッシュへ書き込まない。失敗内容として保持するのは例外クラス名のみ。

## オフライン受入

- show/hide×作品/小説の全経路と原版の順序、重複除去
- 同じ数値のイラストIDと小説IDの分離、メタデータ投影
- 有効な0件取得と失敗の違い
- 4経路それぞれの途中例外、タグ/URL/ID/ページ数の不正形式
- 取得制限、ログ非出力、入力辞書の不変性
- 古い非同期結果の拒否、ローカルにしか存在しない作品の除外、DL済み照合

専用テストは独立レビュー前 **22件成功**。追加のURL制御文字・作品種別/閲覧制限に関する回帰を加え **28件成功**。新規コード込みの統合pytestは **403件成功**（2026-10-22、Windows専用worktree）。差分の独立再レビューは **APPROVE / この純粋アダプタのmerge blockerなし**、CIの最終結果はPRへ紐付ける。

## 未完である受入

実PixivアカウントのGET/POST確認、非公開ブックマークの実API網羅、読取結果の永続キャッシュ、リモート未DL作品の画像プロキシ・ビューア、タグ/小説/うごイラの表示・ダウンロードは未実装。表示専用 `Artwork` に変換するとURL・公開区分・作品種別等の一部情報が失われるため、統合時は必ず元の `RemoteBookmark` を保持する。永続DB互換は `legacy_identity=(raw_id, is_novel)` を用い、UIの `novel:<id>` をDBキーとして保存しない。今回の成功を「実アカウントのブックマーク操作が完了」とは扱わない。

実アカウントでの追加→解除はユーザー承認があるが、限定試験の呼出自体が安全性チェックでブロックされたため行っていない。前回確認されたログイン認証は別の読取試験であり、**書込操作成功・原状態復元の証拠にはならない**。
