# PV「プロダクト開発完了」の定義とフェーズ分解（v2, 2026-11-17）

PV = PixivVault の NiceGUI 移植版。目的は、元リポ（Flet 版 `S:\Projects\PixivVault`、正）の機能・デザインを欠かさず、速さで上回る上位互換にすること。
v2 はアドバイザーと別モデル（Argon）の指摘を反映した版。重要な判断の第三者レビューは Flash でなくアドバイザー・Argon を使う。

## 完了の定義（全て満たしたら「開発完了」）
- **D1 機能同等**:
  - 機能対応台帳（元の操作 → 移植版）を、元から機械的に列挙して作る。対象は、ハンドラ、ボタン・ダイアログの文言、設定キー、ショートカット、右クリック、起動時処理、定期処理。台帳の網羅は `inventory.json` ＋網羅チェック（台帳に無い元の識別子が残っていないか）で担保する。
  - 「無」「弱」がゼロ。例外は本人が除外した 4 つだけ（iOS 連携、Web 連携、Shaft 連携タブ、旧保管庫の取込）。
  - 「有」は、通常起動・実プロファイルで到達できることを意味する（条件付きの機能は条件を満たす起動で実機確認）。
  - 元の自動処理（メタデータ自動補完、類似度の自動推論ほか、台帳に載った全て）は既定を自動実行とし、設定で止められる。元に設定スイッチがあるものはその名前・既定・位置を移植する。
- **D2 デザイン同等**: 全画面が元の見た目契約（トークン、ゴシック＋アイコン）に一致。固定した画面サイズ（1280×800 と 1920×1080）で、通常データ・空データ・長文データの画面証拠（機械検査＋目視、1 フォント p3）がある。見切れ・ズレがない。機能ごとに元の画面との並置比較を行い、記録する。
- **D3 公式 45 残件**: fail ゼロ。partial 39 は PASS か、「物理操作が要る」区分（通知領域・URI 登録・実シンボリックリンク・実マウス・GPU 等）に分類し、可能な範囲は実機で確認済み。「可能な範囲」は項目ごとに理由を書く。区分 D（元 GUI との同条件比較）は D2 の画面証拠で確認する。
- **D4 テスト品質**: 全体テストの失敗ゼロ。ゼロにできないものは、1 件ごとに原因・影響・非関連の根拠を記録し、環境起因（ネットワーク・トレイ等）に限る。全体実行でだけ落ちるテストは原因を特定して直す（記録だけで済ませない）。UI の自動回帰（Playwright の主要画面スモーク）を持ち、各フェーズで実行する。checker（Opus）の指摘がゼロ、残すものは理由つきで記録。
- **D5 実機・データ保全**:
  - 主要導線の一覧（起動、ダウンロード、キュー、失敗リスト、重複整理、学習、ランキング、ライブラリ、おすすめ、自分のランキング、設定、借用 ON/OFF）を実機で、再起動を挟んで確認。
  - 実データ（学習履歴・ライブラリ）は、操作の前後で DB 整合チェックとハッシュ照合を行い、壊していないことを示す。
  - 不可逆操作（ごみ箱を空にする等）は、複製プロファイルで先に実証してから実機へ。
- **D6 応答性**: 学習・ライブラリ・画像送りの操作を、同じ規模の隔離実データ（画像枚数・DB 件数を明記）で、元（Flet 版）と移植版の両方で測定し、同等以上であることを示す。元が隔離データで起動できない場合は、別の証拠方法を定める。
- **D7 安全**: 自動通信はすべて取得停止ゲートを通り、網羅検査がある。新規ファイルを C ドライブに作らない（全体実行の前後で C ドライブの差分を検査）。Cookie・トークン・固定の開発パスワードが、ログ・テスト出力・Git 履歴・STATUS に残っていない（機械検出）。
- **D8 記録**: STATUS/HANDOFF、台帳、証拠、メモリが最新。変更は commit・push 済み。
- **D9 データ互換（上位互換）**: 元の既存 DB、設定、cookies.txt、保存フォルダーを移植版が読める。互換性は台帳の行として管理し、テストする。
- **D10 引き渡し**: 完成したコードの置き場所と、本人が起動する手順（起動スクリプトまたはショートカット）が決まり、動作確認済み。固定の開発値（パスワード、`DEFAULT_UID_PATH` の絶対パスなど）は、元の探し方に合わせるか、変更が必要なものとして一覧にしてある。

対象外: α 版の配布準備、iOS/Web 連携、元に無い新機能。

## フェーズ（機能ごとの出口に、元との並置比較と取得停止ゲートの検査を含める）
- **P0（完了）**: fail 5 件、借用の復旧と実機確認、隔離環境での画面検証。
- **P1 取り込み・安定化**: wt-d（取込済み）、wt-g、wt-e の検査（checker）、wt-f（checker 後）を 1 件ずつ取り込み、全体テスト・CRLF 確認。全体実行でだけ落ちるテストを原因から修正する。UI の自動回帰スモークの土台を作る。ごみ箱を空にする機能は、複製プロファイルでの実証を取り込みの前に行う。実機を再起動して確認。出口: 失敗が基準版以下（以後は減らす方向）、新規の不安定なテストなし。
- **P2 台帳と土台**: 機械列挙の台帳（D1）、`inventory.json`、網羅チェック。元アプリを隔離データで起動できるか確認（D2・D6 の方法を確定）。**共通シェル（ナビ・ヘッダー）を元の見た目へ戻す**（後の機能 UI が壊れないよう先に行う）。出口: 台帳レビュー済み（アドバイザーと Argon）、P3〜P4 の作業リストと規模の確定。
- **P3 機能の完成**: 台帳の無・弱を機能単位で実装（自動実行の既定＋設定、Cookie 自動抽出・別アカウント検出・自動フォロー同期、学習リセットの位置、データ互換 など）。各機能は red→green→checker（取得停止ゲート・元との並置を含む）→実機。出口: D1、D9。
- **P4 公式 45 残件**: OLD45 の A〜E に沿って処理（C 区分は既定案で確定済み: L17 追随しない、S13・U16・X09 互換は元に合わせる）。出口: D3（区分 D は P5）。
- **P5 デザイン証拠**: 共通シェルと、手を入れていない画面を元と並置比較し、固定サイズで画面証拠を撮る。区分 D の比較を兼ねる。出口: D2。
- **P6 応答性と安全**: 元と移植版の測定、改善。取得停止ゲートの網羅検査、C ドライブ差分、機密検出。出口: D6、D7。
- **P7 総合検査**: 全体テスト、UI 自動回帰、checker 総点検（機能退行・デザイン・安全）、実機通し、複製プロファイルでの不可逆操作。出口: D4、D5。
- **P8 クローズ**: 台帳・STATUS・メモリ・引き渡し手順（D10）、commit・push。本人へ最終報告と、物理操作区分の確認依頼（NG の場合の差し戻し手順つき）。出口: D8、D10。

## 運用
- 各フェーズは「実装（Sonnet、作業ツリー別・1 ツリー 1 書き手）→ checker（Opus）→ 実機確認 → 取り込み → commit/push」。
- 区切りごとにアドバイザーへ方針を上申する。第三者レビューは、アドバイザーと Argon（Flash は推奨しない）。
- 外部の利用上限で止まったエージェントは、再開して続ける。
