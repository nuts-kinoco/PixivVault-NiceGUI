# 画像の表示面積と折りたたみツールバー

> **統合済み・参照用。** ここには先行設計の試算と基準寸法を残す。最新の配置、候補タグの初期状態、125% の扱い、監査条件、統合版の実測は [ナビゲーション再編と画像の表示面積](UI_NAV_RESTRUCTURE_20261122.md) を使用する。

対象は全 13 画面。ライブラリは作者一覧と作品一覧を別に測る。操作は現在のメニュー、ダイアログ、検索、取得停止の導線を引き継ぐ。[原受入 A17・B9](../UIUX_AUDIT_SPEC_20261122.md) · [先行候補の計測台帳](../../../ui-img-20261122/verify/uiimg-20261122/r1/IMAGE_AREA.md) · [当初の配置と寸法](UI_IMAGE_AREA_20261122.html)

## 推奨案

全タブで **折りたたみツールバーを 1 部品**として使う。最初は 1 行に画面名、現在の条件チップ、主要操作、開閉ボタンを配置する。カスタムランキングでは選択タグ、取得・更新、絞り込みを常時表示する。展開すると、R-18、AI 除外、よく効くタグ、検索、カードサイズ、その他の絞り込みを操作できる。件数と完了時刻は主操作と同じ行の末尾に置き、狭幅では補助行に流す。停止、通信結果未確定、読み込み、エラーは展開状態に関係なく表示する。

画面の上部は、赤い本番 DB 警告、ロゴ・ログイン状態・API 切り替え・取得停止確認・既存アイコン、タブの順。ロゴと操作を 1 行にまとめ、幅や通知内容に応じてヘッダーを 2 行にする。警告は短いパディングで常時表示し、保存先と意味が分かる。等幅タブの順番と既存アイコンを維持する。標準倍率では短い可視ラベルで 1 行を目指し、完全な操作名をツールチップ・アクセシブル名に付ける。拡大や長い翻訳で 1 行に収まらない場合は折り返す。

開閉状態は画面単位で保存する。既存の「よく効くタグ」の開閉設定も読み戻す。絞り込み値、選択、検索中の入力、一覧スクロール位置を展開時に維持する。トグルには `aria-expanded` と `aria-controls` を設定し、内部から Escape で閉じる場合は開閉ボタンへフォーカスを返す。IME 変換とキーボードショートカットの優先順は既存のまま。非表示中も状態の変化を読み上げ、動作中の停止ボタンは鍵盤・ポインターで操作できる位置に固定する。

## 効果の比較

実測では、1950×1030 のカスタムランキングで一覧が y=523.5、画像が y=560.2 から始まり、一覧は 47.7% を占める。タブはこの候補ではすでに 1 行で 32 px。画面上部のレイアウトだけでなく、候補・選択条件 64 px、状態 39 px、検索とカードサイズ 56 px、および各行の余白を優先して圧縮する。[先行候補の実画面の並置](../../../ui-img-20261122/verify/uiimg-20261122/r1/normal/1950x1030-dark-100/personal/paired.png)

試算の比較条件は一般的な全幅グリッド。1280×800 では左右計 20 px を除く 1260 px、1920×1080 では 1900 px を一覧の幅とし、下端の余白 10 px とする。現状の領域開始が y=500 の場合を共通の出発点に置いた。1950×1030 でも同じ仮定で計算した。各案は単独の効果で、縦区間が重なるため単純加算はしない。

| 案 | 縦に戻る面積の式と想定 | 1280×800 | 1920×1080 | 1950×1030 | Flet の契約と影響範囲 |
|---|---|---:|---:|---:|---|
| 現状の比較起点 | y=500 | 35.7% | 52.2% | 50.0% | 本人の観察を使った試算上の起点。実測は台帳 |
| 折りたたみのみ | 120–180 px、中央の 150 px で算出 | 54.1% | 66.0% | 64.4% | 既存フィルターの開閉と設定保存を踏襲。共通部品と各ビュー |
| ヘッダーの再配置のみ | 40–70 px、55 px で算出 | 42.5% | 57.3% | 55.3% | ロゴ、状態、API、6 アイコンと常時警告の順を維持。`shell.py`、`theme.py` |
| タブ 2 行→1 行 | 32 px のタブと 6 px の行間。もとが 1 行の条件では 0 px | 40.4% | 55.7% | 53.6% | タブを等幅にし、並びを保持。`shell.py`、`theme.py` |
| 赤い帯を薄くする | 現状 37 px、設計 28 px で 9 px | 36.8% | 53.1% | 50.8% | 赤色と本番 DB 警告の機能を維持。`shell.py`、`theme.py` |
| スクロール方向で隠す | 初期 0 px、下へ進んだ後最大 140 px、上へ戻ると 0 px | 35.7–52.9% | 52.2–65.1% | 50.0–63.4% | 内部スクロールごとに挙動制御が要る。フォーカス、スクロール位置、表示の安定を追加検証。共通部品、各スクロール枠 |
| 推奨構成 | コンパクトなシェル＋1 行の折りたたみ。通常時の一覧開始を y=196 までに収める | 73.1% | 80.1% | 79.2% | 初画面から効く。警告とフォーカスの位置を固定。共通部品と各ビュー |

スクロール方向による自動開閉は、初画面を改善せず、逆方向操作や小さなスクロールで操作位置が変わる。推奨構成ではユーザーが開閉を選ぶ。狭幅・拡大で折り返した場合や永続的な警告のある状態も既存の状態表示を維持し、その画面の数値を台帳に残す。

幅の小さい画面は縦だけ縮めても目標に届かない。一般式は `可視幅 / 画面幅 × 可視高 / 画面高`。可視幅が画面幅の 94% なら、55% に必要な高さは 800 px 画面で約 468 px、60% に必要な高さは 1080 px 画面で約 690 px。次の調整を組み合わせる。

| 画面 | 設計上の扱い |
|---|---|
| ランキング／カスタムランキング | 取得前後の条件と結果状態を同じ座席に置く。検索・カードサイズは展開内。最初に両画面で A17 を再計測する |
| ライブラリ／マイブックマーク | DL 済み・マイブックマークの切替と選択中の操作を出す。検索・サイズ・表示範囲・並び順を展開内へ。作者詳細の戻る操作は固定 |
| 重複整理 | スキャン・結果モード・ごみ箱の導線を固定。隔離確認中の状態と選択件数を維持。残りをスクロール一覧に渡す |
| おすすめ | 主要操作と状態だけを固定。棚の見出しと作品は一緒にスクロールし、候補タグは展開内へ |
| 閲覧履歴 | ヘッダーから開くモーダルのまま、上下左右に各 32 px を残す可変幅・高さとする。見出し、説明、操作に 104 px を見込むと一覧は約 75.0%／81.6%。削除確認と閉じる動線は維持 |
| ダウンロードの作者一覧 | 現在の左右分割を基本に、初画面で作者の選択を主役にする。選択の要約と開始ボタンを固定し、対象詳細は同じトグルで開ける。作者一覧に全幅の 94% と y=196〜H−94 を確保する設計なら約 59.9%／68.8%。行や列を縮小する必要はない |
| 学習 | 作品画像と判定四択を常時表示し、左右レイアウトと画像の contain を引き継ぐ。画面上部の切替だけを共通部品に接続し、画像、判定バー、概要・傾向が占める図形を不用意に組み替えない |
| キュー、失敗リスト、メタデータ補完、定期チェック | 再試行・停止等の主要操作と状態を固定。検索・カテゴリ・管理設定を展開内から操作する。文字一覧は参考指標として計測 |

## 実装順とファイル所有

UI 修正担当 1〜5 の統合後、統合候補で A17 を再計測し、差分の影響を確認する。その候補を土台に、共通担当が部品 API・既定値・テストを固めてから各タブが接続する。各担当は下表のファイルだけを書く。

| 担当 | 所有ファイル（`src/pixivvault_nicegui/ui/` 配下） | 段階 |
|---|---|---|
| 1 共通 | 新規 `collapsible_toolbar.py`、`shell.py`、`theme.py`、`gallery.py` | 共通操作、保存先、テーマ、フォーカス、ランキング共用の検索・サイズの配置。呼び出し口を先に共有 |
| 2 設定・確認 | `preferences_view.py`、`shared_get_recovery_view.py`、`premium_recovery_view.py` | 密度変更後に既存確認導線とボタンの意味を照合。必要な修正だけを担当 |
| 3 管理タブ | `unified_download_view.py`、`managed_download_view.py`、`download_status_details.py`、`job_views.py`、`failed_records_view.py`、`duplicate_view.py`、`metadata_view.py`、`scheduler_view.py` | 作者一覧・重複整理を先に接続し、キュー・失敗・管理タブを続ける |
| 4 ライブラリ | `library_view.py`、`library_filter_panel.py`、`bookmark_view.py`、`view_history_view.py` | 作者・作品・ブックマーク・履歴。選択の保持と作者一覧への復帰を検証 |
| 5 発見タブ | `ranking_view.py`、`personal_ranking_view.py`、`learning_view.py`、`recommend_view.py` | 両ランキング、おすすめ、学習の順。学習の基準値を最後のゲートにも使う |

永続化は既存設定の扱いと互換性を共通担当が確認する。設定のスキーマに変更が要る場合は `preferences.py` を共通担当だけが所有する。設定の変更対象はツールバーの表示だけで、既存の取得タイミング、取得停止ゲート、Cookie、認証には手を加えない。

## 再計測と判定

- 112 条件を同じ合成データ、サイズ、倍率、テーマで再計測する。1280×800 の 55%、1920×1080 の 60% は A17 の対象画面ごとに判定する。展開状態も撮影し、閉じた状態の値と別に記録する。
- 学習は、各条件の画像の可視幅・高さ・面積を修正前と照合する。1024×768 は 525.3×394.0 px、1280×800 は 618.6×464.0 px、1920×1080 は 1042.6×782.0 px、1950×1030 は 976.0×732.0 px が下限。両テーマとも同値。1200×900 px の同じ合成素材を使い、判定操作の到達性も確認する。ひとつでも基準を下回れば見直す。
- タブの往復と再起動で開閉・検索条件・選択・スクロールの復帰を確認する。A3、A11、A12、A13、A15 と、停止・エラー・警告時の画面を再確認する。
- 元 Flet との並置で色・書体・表示文言の意味と操作を照合する。本人の密度変更の指示を適用し、既存裁定のライト背景・タブ等幅・並びを守る。B9 の独立判定とネイティブ目視は監督が回収する。
