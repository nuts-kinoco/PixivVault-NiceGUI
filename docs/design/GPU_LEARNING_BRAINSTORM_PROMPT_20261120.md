## 確定した前提（元リポの調査。file:line は元リポ）
1. **学習タブは今、絵柄を画像から学習していない。** 順位付けは 100% メタデータ: タグの Wilson 下限（題材）と作者の Beta 事後平均（絵柄の代理）を 50:50 で合成（`discovery_ranking.py:157-159`、`SCORE_WEIGHTS`）。`hate(style)` は作者 ID の `hate_count` にだけ効く（`database.py:161-168`）。絵柄を画像特徴で覚える経路は存在しない。
2. **「画風タグ案」と「EgaraNet 埋め込みによる絵柄学習」は別。** 前者は 2026-08-06 に棄却（pixiv の画風タグ付き作品が 250 件中 5 件）。後者は設計上の本命（フェーズ M-3「絵柄を学習軸へ」）として合意されたまま**未実装**。実装済みは M-1（埋め込みの走査パイプライン）と M-4（ライブラリの「似た絵を探す」）だけ。過去に一度だけ、ライブラリタブの「好みかも順」にいいね済み作品の style 埋め込み平均を使い、10 時間後にタブ再設計で廃止された履歴がある（6ae2f069→b92d746f）。
3. **EgaraNet の埋め込みの作り方（元の実装）**: 対象はローカルに**保存済み（DL 済み）の画像だけ**（作者 ZIP／フォルダ。長辺 512px、16 の倍数）。サムネイルや学習タブの先読み画像から作る実装は無い。作成は CPU 専用（アプリ内 `INFER_THREADS=2`、onnxruntime CPU。DirectML は Reshape 非対応、可変解像度のためバッチ不可）。1 枚あたり約 1.2〜2.9 秒。保存先は DB の `work_embeddings`（`work_id, kind(style|composition), model="egara_net_fp32", page, dim=1024, vec=float32 L2 正規化済み`）。契機は DL 保存完了時・起動時・手動の 3 つ。
4. **候補（未保存の作品）には埋め込みが無い。** 学習タブの候補はメタデータ（ID・タグ・作者・サムネ URL）だけを持ち、画像は順位付けの**後**に、表示用としてメモリへ先読みされる（先頭 4 枚をスコア差 0.05 以内で保護。`discovery_tab.py:977-1060, 1346-1373`）。永続の候補プール（合意書 §10-4）は未実装（メモリ上の薄い在庫 10〜40 件）。pixiv には画像で画像を探す API が無く、「近さを測れるのは、画像が手元にある作品だけ」。モデル選定書は、候補全体に絵柄を効かせるにはどこかで画像を取りに行く必要がある（合意書 §10-1「候補は 0 リクエストで貯める」を破る）と整理し、案 C（2026-08-07 決定）は「保存済み＋表示用に落ちた画像だけを、落ちた時点で走査」。ただし案 C の「表示用に落ちた画像」への適用は未実装。800 件の候補を裏で DL するとダウンロード約 23 分＋CPU 推論約 28 分、という見積りがある。
5. **移植版の前提（元と同じ）**: 通信は取得停止ゲートを通す。Pixiv へのレート制限（約 1.15 req/s）を圧迫しない。移植版にも `LearningImagePrefetch`（先読み）がある。

## 制約
1. 元の学習の挙動を壊さない。GPU 学習は「追加の補助スコア」で、設定で止められ、止めると元の順位付けに完全に戻る。永続ストアを汚さない（別ファイル・別テーブル。無くしても本体が動く）。
2. 通信を増やさない（自動通信はゲート経由）。画像の追加取得が要る方式は、その通信量・取得対象・ゲートの扱いを明示すること。
3. ローカル完結（画像・判定履歴・埋め込みを外部へ送らない）。依存の追加は、導入の重さ・Windows での入手性・RTX 5080（Blackwell）での動作・オフライン起動を理由付きで評価する。
4. Undo・再判定・全削除に追従できる。常駐ではなく、アイドル時・手動・設定でのスケジュール。VRAM を Egara 類似検索・WD タグ付け・本体と奪い合わない。

## 私（Claude）の仮説（批判してほしい）
- **絵柄の学習で最大の問題は、候補に画像が無いこと。** 選択肢は (A) 学習は保存済み・ブクマ済みの画像（ローカルにある）で行い、候補への適用は「表示用に先読みで落ちた画像」の範囲に限る（案 C）、(B) 候補を先にプールして画像（サムネイルか本画像）を取得してから評価する、(C) サムネイル（小さい画像）の埋め込みで代用する、(D) 作者単位の絵柄ベクトル（その作者の保存済み作品の平均）で未保存の候補を作者経由で評価する、の 4 つ。**(D) は通信を増やさず、元の「作者＝絵柄の代理」を、画像特徴で強化する形になる**ので、最小の第一歩として有力では？
- 判定数が少ないうちは、MLP より、埋め込み空間の近傍・プロトタイプ法（正例の重心との類似度、負例からの距離）が安定する。
- skip は「嫌い」ではなく「今は興味がない」のノイズを含む。hate(style) だけを絵柄空間の負例に、hate(genre) と skip は絵柄空間に使わない。
- 保存・ブクマ済みの作品は大量の正例だが、選択バイアス（絵柄以外の理由）がある。重みを下げるか別ヘッドにする。
- 評価は判定履歴の時系列分割（過去で学習し、直近の判定を予測。AUC・NDCG@k）。オンラインの A/B ができない個人利用の唯一の客観指標。
- GPU は「使い切る」ことが目的ではなく、**既存の保存画像（数万枚規模）の埋め込みの一括事前計算（元は CPU で 1 枚 2 秒前後のため、数万枚だと現実的でない）**と、複数モデルのアンサンブル、再学習に使うのが効果的。まずは元の CPU 版 EgaraNet を GPU（onnxruntime-gpu CUDA、または PyTorch）で高速化できるか、RTX 5080 での実行可否が先決。
- 説明可能性（「最も近い好み作品 3 枚」を表示）は、効果を本人が体感する仕掛けになる。
