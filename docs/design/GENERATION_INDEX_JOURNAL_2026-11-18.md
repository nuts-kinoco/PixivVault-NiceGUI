# 世代インデックスのジャーナル（版 5）2026-11-18

対象: `managed_generations.py`。保存作品が数万件でも保存・検証が遅くならないための構造と、その限界。

## 構造

- `active-generations.json`（索引）は検証済みの土台。版 5 では `journal.id` を持つ。
- `active-generations-<id>.journal` は、土台のあとに保存された作品を 1 行ずつ追記する（hash 連鎖）。
- `active-generations-<id>.mark` は `{id, records, chain}`。追記のあとに書き換える。
- 畳み込み（索引の書き直し）のたびに id が変わる。新しいジャーナルとマークを先に作って durable にし、そのあとで
  索引を差し替える。古いジャーナルは 120 秒だけ残す（古い索引を読んでいる読み手のため）。
- 旧コード（版 1〜4 だけ知る）は版 5 の索引を拒否する。ジャーナルを黙って無視して作品を消す・巻き戻すことはしない。

## 何を検出し、何を許すか

| 状態 | 扱い |
|---|---|
| ジャーナル・マークの消失、空化、短縮、途中切れ、hash 連鎖の不一致 | 拒否（作品が減ったとは読まない） |
| ジャーナルの最後の 1 行が書きかけ | 無視（保存は確定していない） |
| ジャーナルがマークより先（クラッシュ、マーク書き込みの失敗） | 許す。次の保存が、追記する前にマークを追いつかせる。追いつかせられなければ追記しない |
| マークがジャーナルの連鎖上の点でない／ジャーナルより先 | 拒否 |
| 索引（版 5 未満）が作品を 1 件も持たないのに generations/ に作品がある | 拒否（旧ジャーナルが消えた疑い） |

## 設計上の限界（検出できないもの）

索引・ジャーナル・マークを**そろえて**古い状態へ戻す（フォルダー全体をバックアップから戻す）ことは、
復元と区別できない。古い状態として読まれる。バックアップはフォルダー全体で取ること。

カタログの検証キャッシュは、サイズも更新時刻も同じ静かな破損を、期限（約 30 分）か開き直しまで見逃す。
ページを読む時は常にハッシュで検出する。期限後に壊れた作品が 1 件あると `catalog_snapshot` 全体が失敗するが、
例外の `work_id` / `relative_receipt` が壊れた作品を示す。
