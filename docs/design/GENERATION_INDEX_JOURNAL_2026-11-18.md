# 管理領域の世代索引とジャーナル

`managed_generations.py` は、作品の不変な受領書とページを世代付き索引で公開する。現在の索引形式は、世代付きジャーナルと連番付き head を持つ版 5。版 1〜4、世代のない旧版 5、連番のない旧 head、旧ジャーナルおよび旧アップグレード途中の状態は移行せず拒否する。既存の復旧画面からバックアップの復元を案内する。

索引とジャーナルのヘッダ、`.mark`、新しく保存する受領書には generation を記録する。既存の有効な現行形式で保存済みの受領書は書き換えない。索引の検証は `assert_consistent` に集約し、保存・畳み込み・隔離の確定前にも書込みロック内で検証する。保存前と公開直前の両方で容量を再判定し、上限は 100 万作品・1 GiB とする。

畳み込みでは次世代のジャーナル、`.mark`、索引候補を準備領域へ書く。generation-floor の耐久化が確定点で、head と索引の反映が中断された場合は候補から完了する。確定前の準備物は旧世代の巻き戻り証拠ではなく、次の書込み時に整理する。確定済みの floor は、索引と head を共に戻した場合にも新しい世代を示す。

同一世代の追記は連番とハッシュ連鎖で検証する。追記前に準備記録を置き、ジャーナルの fsync 後にその確定記録を耐久化する。確定前の完全行や途中までの行は公開しない。確定記録がある追記の行が欠けた場合は拒否する。head や `.mark` の反映が中断された場合は、確定記録と連鎖を検証して再開できる。

検出対象は、索引・head・現行ジャーナル・`.mark` の一部だけの巻き戻し、同一世代の後続追記の喪失、および準備中・確定前後の中断である。**ルート全体を一式で古い状態へ戻した場合は検出できない。** バックアップはフォルダー全体で取る。

ページは実際に読むときにハッシュを検証する。カタログの検証キャッシュは、サイズも更新時刻も同じ静かな破損を、期限または再オープンまで見逃すことがある。
