## 推奨設計

### タブとヘッダー

| 順 | 画面 | キー / Material アイコン |
| ---: | --- | --- |
| 1 | ダウンロード | `download` / download |
| 2 | キュー | `queue` / queue |
| 3 | 失敗リスト | `failed` / report_problem |
| 4 | 重複整理 | `dedup` / content_copy |
| 5 | 学習 | `learning` / explore |
| 6 | ランキング | `ranking` / leaderboard |
| 7 | カスタムランキング | `personal` / military_tech |
| 8 | ライブラリ | `library` / photo_library |
| 9 | マイブックマーク | `bookmarks` / bookmarks |
| 10 | おすすめ | `recommend` / recommend |

Flet の画面順とランキング 2 画面の隣接を保つ。 `tab-bookmarks` を加え、主ナビの `tab-scheduler`／`tab-metadata` は `automation-open` とダイアログ内の選択先に移す。 `history` は起動互換とヘッダー操作のため維持する。主ナビは等幅・アイコン付き・全ラベルとし、`aria-current=page` は背景の選択中タブだけに付ける。既存の Tab／Enter／Space と画面内ショートカットを維持する。制限付き起動で使えない操作には従来の条件と理由を適用する。

右上は「バックアップ → 閲覧履歴 → 自動処理 → 保存フォルダー → テーマ → Pixiv → 設定」。7 個を 40 px、間隔 4 px とすると 304 px、6 個からの増分は 44 px。バッジはボタンに重ねる。タブとアイコンは別の行。警告、ログイン状態、API 切り替え、取得停止と回復は常時到達できる。狭幅ではヘッダーの左側と操作列を次行へ流せる。アイコンにはツールチップとアクセシブル名を付ける。

現行 CSS の 162 px 固定では、10 個でも `10 × 162 + 9 × 8 = 1692 px`。可変等幅にし、左右各 12 px、間隔 4 px の例で、1280 CSS px なら 1 タブあたり 122 px、1920 CSS px なら 186 px。全ラベルとフォーカス枠が見える最小幅を実フォントで測り、標準倍率では 1 行を目指す。狭幅・拡大時は折り返す。FL-V03 には 1280px で全項目を見せる 2 段裁定があるため、1 行案は 1280px で全ラベルと操作域が見える証拠を添えて監督が整合を確認する。代替案は 1280px で等幅 5×2、1920px で 10×1。横スクロールは一部の項目が隠れる。

### マイブックマーク

- 初回訪問に既存の `BookmarkView` を一度だけ生成して保持する。ライブラリの旧切替を外し、DL済みの作者一覧 → 作品一覧 → 戻るはそのまま辿れる。ライブラリの初期描画がブックマークを生成・更新する依存も切る。入口はタブに一本化する。
- カード・画像・ページ送り・ビューア、作者と似た作品への遷移、カードサイズ、タグと検索、選択と一括保存、更新、鮮度・取得失敗・キャッシュ保存先の表示を継承。サービスのキャッシュを単一の供給元とする。DL 状態の反映には既存のスナップショット・世代・再投影を使い、作品閲覧中は表示中のカードを動かさない。
- 「pixiv本体も含む」は DL済み側に置き、借用の準備中、許可後・解除後の再検索、失敗からの再検索、遅延結果の破棄を維持する。独立したブックマークは既存のリモート／ローカル投影と明示更新、カード起点の借用依存処理を保持する。両方が使うフィルターでは設定キー・優先順、未取得・ブクマ数・選択の意味を保つ。借用状態が変わったら既存認可経路から関係するビューを更新する。
- 既存キャッシュを採用し、有効かつキャッシュなし／120 秒以上で自動更新する条件を初回と再活性化で評価。アカウント切替、停止・スキップ、保存結果未確定を維持する。検索、選択、スクロールをタブ往復で保持し、非アクティブ化で遅延ビューア・似た作品・画像セッションを失効させる。複数メディア、イラストのみ、サンプル、読み取り専用、イラストのない構成を別々に確認する。

### 自動処理ダイアログ

上限付きの幅と高さを設定し、ヘッダーと切替を固定、本文だけスクロールする。「定期チェック」「メタデータ補完」の選択ごとに初回だけ既存ビューを生成する。閉じて再表示しても未保存値と処理結果を引き継ぐ。所有者・版が変わった場合は既存の検証に従う。設定の「自動処理」に両方への入口を置く。既存スイッチは「作品メタデータ」に一つ置き、「起動時にもチェック」、間隔、停止と再試行、保存、履歴、台帳は各画面内で扱う。

共有ログはダイアログの共通の折りたたみ領域へ移す。既存の開閉・順序・所有者検証を引き継ぎ、切替で複製しない。定期チェックの詳細更新には照合と画面内通知の副作用がある。既存ランナーの照合・デスクトップ通知を維持し、画面内通知の配信をダイアログの可視性から切り離す。共有の原子的な claim、送達直前の所有者検証、既存の通知条件を守る。

| 状態 | 観測する事実 | 右上の表示 |
| --- | --- | --- |
| 待機中 | 自動有効で予定待ち、または一時保留。キュー待ち、取得元確認中などは詳細に理由を出す | なし |
| 実行中 | 定期チェックの現所有者の実行・受理済み処理、またはメタデータの取得実行境界内 | 再生マーク |
| 失敗 | 現所有者の未解消エラー・中断／結果未確定や補完の失敗・要確認 | 感嘆符 |
| 停止 | 設定 OFF、取得停止ゲート、または停止成立。停止要求後も通信が進行中なら実行中として詳細に理由を出す | 停止マーク |

同時に該当する場合は失敗 → 実行中 → 停止。理由は処理ごとに表示し、ツールチップとアクセシブル名で両方が読めるようにする。失敗は成功または既存の確認・回復が観測できた時点で解除する。未提供は「利用不可」、読取り不能は「状態を確認できません」と出す。

**監視。** 現行の詳細 UI は両方 5 秒。シェルの 1 秒タイマーは借用同期と視覚学習の状態表示に使う。推奨案はサービスの既存遷移から所有者検証済みの要約 2 件を保持し、UI は更新差分だけを描く。既存イベントを優先し、必要な場合はクライアントに最大 1 つの 1 秒タイマーでメモリの要約だけを比較する。閉鎖中は詳細 UI のタイマー、台帳集計・履歴取得、通信を行わない。開いた時と表示中だけ、選択中の詳細を即時および現行の 5 秒間隔で更新する。再入防止、閉鎖・切替後に反映しない世代確認、切断時のタイマー／購読解除を行い、所有者変更で古い状態を落とす。バックグラウンドの既定・間隔・開始条件は現行契約を維持する。

**操作。** 入口に `aria-haspopup=dialog`、ダイアログに可視見出しとモーダルの意味を付ける。利用できるパネルから失敗中 → 実行中 → 定期チェック → メタデータ補完の順で最初の選択を決める。設定と起動からの明示パネルを優先する。開いたら選択中の内側タブにフォーカスを置く。左右矢印／Home／End で移動し、Tab／Shift+Tab は本文と閉じる操作をモーダル内で巡回する。Esc は上に開いた確認・ポップオーバーを先に閉じ、IME 変換を尊重する。閉じたら背景タブの入力・位置・選択を保ち、入口にフォーカスを戻す。設定入口は設定を閉じてから開き、閉じたらヘッダーの設定へ。起動指定時は自動処理ボタンへ戻す。切替・閉鎖中も処理は続き、明示の停止ボタンから停止要求する。

**代替案。** 縦積みは両方を同時に見られるが、台帳とログが縦に並び停止操作まで遠くなる。アコーディオンは両要約を見せやすいが、展開位置・フォーカス・監視の調停が増える。2 画面を常時 1 秒でポーリングする案は、クライアント数に比例して台帳アクセス・照合・通知の負荷が増える。ダイアログ内切替と小さい要約を採る。

### 起動先の互換

| 入力 | 起動先 |
| --- | --- |
| 指定なし・保存設定なし、`unified`、内部の `download` | ダウンロード。自動処理ダイアログとランキングの初回取得は発火させない |
| `queue`、`failed`、`dedup`、`ranking`、`library`、`recommend` | 既存の各画面 |
| `discovery`、内部の `learning` | 学習 |
| `history` | 既存のバックアップ画面。利用不可の構成は従来の既定へ |

起動先を選べる設定を製品に加える場合は「明示 CLI → 保存された起動先 → ダウンロード」。明示 CLI が不明・利用不可なら警告してダウンロード。設定キーは任意で、既存設定ファイルはキー欠落のまま読み込める。保存値も CLI と同じ解決関数へ通し、旧値の一括書換えを行わない。 `startup_tab.py` に表示順と別の起動先定義を集約し、`bootstrap.py` で CLI と設定の優先順を決める。内部の `startup_tab` 引数の既存キーも保つ。既定・明示優先・未知値・利用不可・履歴互換・両ダイアログ指定と復帰を試験する。

### よく効くタグと画像の表示面積

- 共通の折りたたみツールバーの展開内に候補を 1 行。既存候補の順、選択処理、件数上限、`ranking_personal_candidates_open` は FL-Y02 に従う。選択中タグ・主操作・エラー・取得停止は固定領域から操作できる。
- 見出しと `+N` の幅を確保し、入る先頭候補を並べる。全部入ればボタンを省き、極狭幅で候補が入らなければ全件を `+N` に畳む。フォント・倍率・文字幅を実寸で再計算する。長い候補はポップオーバー内で折り返す。開いていない候補はフォーカス経路から外す。
- 「残り N 件のよく効くタグを表示」、`aria-expanded` と対象の関連を付ける。Enter／Space で開き、Tab で候補へ移動し、Esc・外側クリック・候補選択で閉じる。Esc と選択時は起点へ、幅変更で起点が消えたら同じ候補か親の開閉へ戻す。選択は既存のタグ追加・検索経路を再利用する。ポップオーバーの開閉は一時状態。横スクロールの代替は一行を保てるが、残り候補の存在と件数が分かりづらい。
- [画像の表示面積設計](../../../ui-img-20261122/docs/design/UI_IMAGE_AREA_20261122.md) の共通折りたたみと詰めたヘッダーに接続する。同設計のライブラリ内切替を独立タブで読み替える。1280×800 で 55%、1920×1080 で 60% の A17、学習画像の基準下限、B9、112 条件の既定分母を維持する。実装候補で通常・展開・空・長文・エラー・取得停止、ライト／ダーク、狭幅・倍率上昇を再計測する。[監査仕様](../UIUX_AUDIT_SPEC_20261122.md)
