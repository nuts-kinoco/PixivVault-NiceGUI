| # | 覆った前提 | 根拠（コード確認済み） | 計画への影響 |
|---|---|---|---|
| 1 | 「学習タブの 3 枠の順位を補正すれば、おすすめで効果を体感できる」 | 学習タブの順位（`discovery_learning.py:430`）とおすすめの順位（`recommendation_state.py`／`recommendation_acquisition.py`）は**別経路**。偽データで再現。本人の確定事項は「おすすめが主役」 | 適用先の第 1 候補を**おすすめの「好みの傾向から（確実）」節**に変更。学習タブへの適用は別の作業単位 |

## 2. 本人の確定事項との整合

壁打ち §25 の確定事項（ゼロデータ開始、未知との出会い最優先、おすすめが主役、取得方式 B 許容、複数モデル可、ワンボタン停止、Skip は学習タブ限定、全ページ解析、NG 属性は本人承認のみ）と、壁打ち前半の推奨（B 不採用、D 本命）には食い違いがある。整理:

- **ゼロデータ開始なので、作者ベクトル D は当面効かない**（D の材料は「その作者の保存画像」。保存画像ゼロでは初期カバー率 0%）。よって最初の効かせ先は **A（画像を取得できた候補の作品単位の絵柄）**。D は保存が溜まってから効く補助。
- **B（候補画像の追加取得）は、本人は許容済み**だが、計画は 2 段階にする: フェーズ 1〜2 は追加 GET 0（B なし）で測る。B はフェーズ 3 で、取得停止ゲート・全体の通信予算・容量上限に従う上限付きで、効果が実測で示されてから。B を先にやらない理由は、通信・待ち時間・停止制御が重く、効果が未測定だから。
- **全ページ解析・棚 UI・タグ掛け算・NG 属性・両タブからの即時除外**などの全体要件は、この計画の範囲外（別の大きな案件）。フェーズ 2 までで入れるのは「絵柄の補助スコア」だけ。

## 3. 製品への落とし込み

**データ**（所有マーカー `.pixivvault-visual-preference-v1` と固有 application_id を持つ独立ルート。S: のみ。既存の `learning.sqlite3`・「似た絵を探す」台帳は読み書きしない）
- `candidate_embeddings`: 作品・ページ・変種（保存原画／表示画像／サムネイル）・画像 SHA-256・モデル SHA・前処理版・FP32 ベクトル。404 フォールバックのサムネイルは別変種として区別。
- `ranking_events`（追記専用）: 提示した候補集合・当時のベース順位と枠・画像の可用性・判定とリビジョン。80:20 の時系列分割が成り立たないため、**前向き記録で評価する**（現行履歴は再判定で上書き・Undo で削除されるため）。
- `preference_models`: 学習世代、判定リビジョン指紋、プロトタイプ。判定確定・理由変更・Undo・復元・リセット・画像差替・モデル変更・OFF・アカウント切替で世代を即時失効し、完了時と UI 適用直前の両方で世代を照合。

**契約**
- OFF・画像なし・モデル不一致・古い世代・GPU 失敗では、補正を計算せず現行の順位と**完全一致**（加算演算も行わない）。
- 表示中・操作中・保護対象のカードは動かさない。補正は次の表示スナップショットで、画像が準備済みの候補だけに適用。
- 視覚学習が起こす GET は 0（ワーカー単体で dispatch 0。順位適用経路で既存操作に対する追加 GET 0）。偽 transport と `required_network_guard` で試験。
- 同時 GPU ジョブは 1。`LocalTagger`・他の GPU 利用（EMA のリース）と排他。実行は低優先・協調停止・停止時 VRAM 解放。

**画面**（既存のトンマナを崩さない配置。Argon の案を採用）
- 設定の「絵柄・構図の推論」グループに 3 項目を追加: 視覚補正の ON/OFF（既定は OFF＝シャドー記録のみ）、実行タイミング（アイドル時／手動）、実行状態の行（待機中／解析済み N 件（残り M）／学習世代／実行先 GPU／追加 GET 0 件）と、いま解析する・停止（ワンボタン）・視覚学習データ削除（保存作品・判定履歴・類似台帳は消さない、と明記する確認つき）。
- 学習タブ: 判定ボタンの位置は変えない。「探索の設定」の重ね置きパネルに ON/OFF と状態、候補ヘッダーに「近い保存作品 ▸」（最大 3 枚＋類似度）、モード切替に「順位の比較」（名前を伏せた A/B 比較）。
- 設定画面の UI 変更は、いま進行中の UI トンマナ修正（担当 D）の後に載せる（所有ファイルの衝突を避けるため）。
