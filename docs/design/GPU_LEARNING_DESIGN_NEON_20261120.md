## 2. GPU 学習の選択肢比較と推奨案
| 案 | 方式 | 期待効果 | VRAM / 時間（推定） | 実装量 | 主なリスク |
|---|---|---|---|---|---|
| **(a)** | 多空間画像埋め込み（Egara＋SigLIP＋WD特徴）＋軽量分類器（Logistic/残差MLP） | **高**: 絵柄・構図・題材と非線形組合せを学習し候補を再順位付け | 推論 6〜10GB / 1万枚数分、学習 1〜2GB / 数秒 | 中 | 判定少数期の過学習、サムネと原画の解像度差 |
| **(b)** | 保存済み埋め込みの球面クラスタリング（多峰性嗜好）＋クラスタ別探索 | **中高**: 複数の嗜好群を分離し、未知作者の「好み絵柄近傍」を発見 | 1〜2GB / 数秒（GPU行列演算） | 小〜中 | 保存済みは全肯定のため拒否（`hate`）境界を作れない |
| **(c)** | 視覚バックボーンの LoRA 微調整 | **不安定**: 個人判定数百〜数千件では過学習・破滅的忘却が起きやすい | 12〜15GB / 数十分〜時間 | 大 | Undo/再判定や設定OFFの即時追従が困難、保守コスト過大 |
| **(d)** | 候補取得前のサムネイル大量先読み＋事前フィルタ | **中**: 枠に入る前にハズレを除外 | 推論 4〜8GB / 毎バッチ数秒 | 中 | Pixiv レート制限（1.15 req/s、[`discovery_engine.py:73-81`](file:///S:/Projects/PV-DEV-20261117/work/src/pixivvault_nicegui/discovery_engine.py#L73-L81)）圧迫と取得停止ゲート違反リスク |

- **推奨案: (a)＋(b) 統合ハイブリッド（多空間埋め込み＋球面嗜好クラスタ＋残差2層 MLP スコアラー）**。理由: RTX 5080 16GB を高スループットな**多空間バッチ埋め込み抽出**（既存 EgaraNet 絵柄1024＋構図1024、新規 SigLIP-SO400M 意味1152、WD SwinV2 ロジット圧縮）と**GPU 上の全ライブラリ球面 K-means（K=4〜12、多峰性嗜好重心）＋残差 MLP 学習**に使い切れる。Undo・再判定・設定 OFF にも数秒の再学習または即時失効で追従でき、(c) の過学習や (d) の通信ゲート違反を回避できる。なお候補画像の事前スコアは独自取得を行わず、既存の先読み [`LearningImagePrefetch`](file:///S:/Projects/PV-DEV-20261117/work/src/pixivvault_nicegui/learning_prefetch.py#L19-L68) で取得済みの画像のみを対象に遅延再順位付けする。

## 3. 推奨設計
### 3.1 データの流れ
1. **埋め込み抽出**: 保存済み原画（[`services.py:846`](file:///S:/Projects/PV-DEV-20261117/work/src/pixivvault_nicegui/services.py#L846) の `images.local_bytes` および既存 [`ManagedSimilarityIndex`](file:///S:/Projects/PV-DEV-20261117/work/src/pixivvault_nicegui/managed_similarity.py#L70-L148) / `CombinedSimilaritySource` の Egara ベクトルを再利用）を GPU バッチ推論し、L2正規化済み連結ベクトル（Egara style 1024 + composition 1024 + SigLIP 1152 = 3200次元 FP16）を独立キャッシュへ格納。
2. **嗜好学習（GPU）**: 教師データは `discovery_swipe_history`（`superLike`=+2.0, `like`=+1.0, `skip`=-0.25, `hate(style)` は Egara 空間へ強い負重み、`hate(genre)` は SigLIP/タグ空間へ負重み）、保存/ブクマ資産（弱い正例・対数減衰）、`discovery_view_history`（複数回閲覧を弱い正補助）を合成（重み係数はオフライン評価で校正・推測）。GPU 上で①肯定集合の球面 K-means 重心 `{c_k}` と最大コサイン類似度特徴を算出し、②`[埋め込み, クラスタ最大類似度, 統計下限]` を入力とする残差2層 MLP（Dropout＋L2正則化＋Platt/温度スケーリング）を数秒で学習。
3. **候補スコア合成（読取時のみ）**: [`LearningImagePrefetch.run`](file:///S:/Projects/PV-DEV-20261117/work/src/pixivvault_nicegui/learning_prefetch.py#L42-L68) が取得済みの候補画像をバックグラウンドで推論し、スコア `v_score ∈ [0,1]` と最寄りクラスタ確信度をメモリ上の不変ビュー `VisualPreferenceView` へ公開。[`rank_candidates`](file:///S:/Projects/PV-DEV-20261117/work/src/pixivvault_nicegui/discovery_ranking.py#L802-L839) は統計スコア `s` と `(1-α)s + α·v_score`（判定件数に応じた信頼度減衰付き、未知作者の絵柄探索枠でも好みクラスタ近傍を優先）で読取時のみ並べ替え、[`finalize_display_order`](file:///S:/Projects/PV-DEV-20261117/work/src/pixivvault_nicegui/discovery_ranking.py#L755-L780) の拒否作者・クォータ契約を維持する。

### 3.3 GPU 環境実測とランタイム選定・VRAM 16GB 配分
- **環境実測結果**: GPU は `NVIDIA GeForce RTX 5080 (16303 MiB VRAM)`、ドライバ `621.24`、`CUDA UMD Version: 13.5`（Blackwell `sm_120` 向け CUDA 12.8+ 要件をドライバ側は充足）。一方 `where python` の全環境およびアプリ本体 venv（`S:\Projects\PixivVault-NiceGUI\.venv`, Python 3.13.11）の `pip list` を確認したところ、**本体 venv には `torch`/`onnxruntime`/`onnxruntime-gpu`/`numpy` が全て未導入**、`stenv` と `Python313` にも CPU 版 `onnxruntime 1.28.0/1.27.0` と `numpy` のみで GPU ランタイム未整備。
- **ランタイム方針**: 特徴抽出＋MLP 逆伝播・球面クラスタリングを一貫して CUDA 実行するため、**PyTorch（CUDA 12.8+ `cu128` wheel、Blackwell `sm_120` 対応）を隔離 GPU ランタイムまたは任意追加依存**として採用（既存 [`egara_inference.py:160-163`](file:///S:/Projects/PV-DEV-20261117/work/src/pixivvault_nicegui/egara_inference.py#L160-L163) の隔離ランタイム思想・[`similar_works.py:8-14`](file:///S:/Projects/PixivVault/similar_works.py#L8-L14) の遅延 import を踏襲）。ONNX 資産（`egara_bb.onnx` / `wd-swinv2`）の GPU 実行には `onnxruntime-gpu`（CUDA 12.8+ 対応版）を併用。未導入時は起動・動作を壊さず統計学習のみへ自動フォールバック。
- **VRAM 16GB 配分（推定値）**: Windows WDDM/ブラウザ描画向けに 2.5〜3GB を常に残し、上限 13GB 枠で使い切る。①モデル常駐 ~2.8GB（SigLIP-SO400M/14-384 BF16 ≈ 0.85GB、EgaraNet FP32 ≈ 1.4GB、WD SwinV2 ≈ 0.5GB）、②バッチ推論ワークスペース ~7〜8GB（384×384/512×512、バッチサイズ 64〜128、BF16 混合精度、OOM 時はバッチ半減リトライ）、③全ライブラリ行列＋MLP 学習 ~1.5〜2GB（例: 5万枚×3200次元 FP16 ≈ 0.32GB を GPU 常駐させ、ミニバッチ 1024 で数秒学習）。なお既存 [`egara_inference.py:37`](file:///S:/Projects/PV-DEV-20261117/work/src/pixivvault_nicegui/egara_inference.py#L37) の `gpu_mem_limit=8GB` 固定値は設定可能に拡張する。

## 4. 検証方法・リスク・やらないこと・最小実装順
- **検証方法**:
  1. **偽データ単体・契約試験**（`pytest -p required_network_guard`）: 同タグだが視覚クラスタが異なる合成ベクトル（2峰性好意＋1拒否クラスタ）で視覚ハイブリッドが統計単体より高い NDCG@10/AUC を出すことを確認。さらに [`argon_redesign_ak_out.md:56-59`](file:///S:/Projects/PV-DEV-20261117/tmp/argon_redesign_ak_out.md#L56-L59) と同型の対照群（常時 OFF）vs 試験群（ON 運用→設定 OFF/モデル改変/非ローカル/画像欠損/GPU 失敗）で、`learning.sqlite3` 全表・検索語・候補順位が完全一致することを検証。
  2. **オフライン時系列評価**: 複製隔離データの `discovery_swipe_history` を `judged_at` 昇順で時系列分割（80%学習→20%検証、かつ未知作者のみの評価スライス併設）し、`like`/`superLike` を正例、`hate`/`skip` を負例として **NDCG@10/20、ROC-AUC、PR-AUC、Top-10 `hate` 混入率** を「現行統計のみ」vs「推奨ハイブリッド」で比較。
- **既知のリスク**: ①Blackwell (`sm_120`) 向け Windows `cu128` 依存のサイズ増と更新追随（隔離ランタイム＋遅延フォールバックで防御）、②学習用原画と推論用候補サムネイルの解像度/JPEG 圧縮差（学習時にサムネイル相当縮小拡張を適用・推測）、③全肯定の保存資産による初期スコア偏り（判定履歴優先のサンプル重み付けと温度校正で緩和）、④他 GPU アプリとの VRAM 競合（OOM 時バッチ半減・上限設定で緩和）。
- **やらないこと**: 視覚特徴からの Pixiv 検索語自動生成、取得停止ゲート外でのサムネイル独自先行ダウンロード、`learning.sqlite3` への派生データ書込み、バックボーン本体の微調整（LoRA 含む）。

  3. `Commit 3`: 球面 K-means＋残差 MLP 学習器、`VisualPreferenceView`（不変スナップショット・即時失効）、オフライン時系列評価スクリプト。
  4. `Commit 4`: [`discovery_learning.py`](file:///S:/Projects/PV-DEV-20261117/work/src/pixivvault_nicegui/discovery_learning.py#L270-L273,L312-L315,L414-L424) / [`discovery_ranking.py`](file:///S:/Projects/PV-DEV-20261117/work/src/pixivvault_nicegui/discovery_ranking.py#L802-L839) の読取時スコア合成＋先読み完了フック＋設定 UI 配線。
