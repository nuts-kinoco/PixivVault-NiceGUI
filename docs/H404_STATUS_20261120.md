# 共有ヘッダーの HTTP 404 修正

対象は `feat-h404`、基点は `pv-dev-baseline` の `f8e2d65`。コードと通信台帳の候補は `b9fd651`。比較元は Flet 版 `S:\Projects\PixivVault` の `3ac3aa0d`。

## 元の表示と修正方針

Flet の共通ヘッダーはログイン状態・連携状態・Cookie の案内を表示する。ログイン確認の通信エラーや認証切れはログイン状態として更新する。個別の GET の試行結果はここに掲載しない。下部の共有ログは別の欄で、タブによって隠れる。元の `_request_with_retry` は HTTP 404 を対象の欠落としてログに記録し、直ちに呼び出し元へ例外を返す。操作側では、学習の画像読み込みエラーやランキングのページ終端などを扱う。 [元 gui.py のヘッダー](<S:/Projects/PixivVault/gui.py:6125>) · [元ログイン状態](<S:/Projects/PixivVault/gui.py:6247>) · [元の下部ログ](<S:/Projects/PixivVault/gui.py:5942>) · [元 pixiv_client.py の 404](<S:/Projects/PixivVault/pixiv_client.py:734>)

移植版は、HTTP 404 をどの種類の GET でも再試行せず、処理中の記録を当該 GET の分だけ取り除き、型付き例外を取得元の画面やジョブに返す。画面ごとの失敗・欠落・終端の扱いは呼び出し元に委ねる。429 の待機と試行上限、401/403、通信断、期限・中止、送信許可判定と永続 STOP は従来の扱いを保つ。 [request_policy.py](../src/pixivvault_nicegui/request_policy.py#L220) · [pixiv_read_client.py](../src/pixivvault_nicegui/pixiv_read_client.py#L799)

元のヘッダーに共有の中止表示やその消去条件がないため、依頼の例外条件に従い、移植版の中止表示の寿命は維持した。次の同一ポリシーの取得開始時（ポリシーの事前チェックを通過した時点）に過去の終了記録を消す。操作が来ない間は中止記録が残り得る。成功した GET は自身の進捗を消す。 [記録の入替](../src/pixivvault_nicegui/request_policy.py#L231)

## 再現した原因

基点の `pixiv_read_client.py:813` では、R3 の例外フラグ `local_not_found` は `kind == 'image'` のときだけ有効だった。その他の GET は 404 を `failed` としてメモリに残し、`RequestStatusView` が共有ラベルに「HTTP 404: 試行 1/3で取得を終了しました。」を描画した。次の取得が始まるまで終了表示が残った。実機 R4 の直前操作と実際に 404 を返した取得先は未特定。 [表示](../src/pixivvault_nicegui/ui/request_status_view.py#L32)
