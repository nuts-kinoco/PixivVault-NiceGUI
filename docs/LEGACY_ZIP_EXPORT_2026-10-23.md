# 管理保存済み原寸画像 → 原版互換ZIP（限定マイルストーン）

## 利用手順

旧PixivVaultのDB・画像・ZIPとは**別の、まだ存在しない専用フォルダー**を選び、次を明示指定して起動する。

```text
--pixiv-cookie-file <既存の認証Cookieの絶対パス>
--pixiv-download-root <NiceGUIの既存専用managed保存root>
--legacy-zip-export-root <新規の、他の保存元と重ならないZIP出力フォルダー>
```

「ライブラリ」→「DL済み」→作者詳細→「旧形式ZIPを書き出す」を押す。NiceGUI自身が**全ページをSHA検証した保存済みアクティブ世代だけ**を、`作者名(作者ID).zip` に出力する。原版 `core.py` の `sanitize_filename` と `illust_save_filename` / `work_id_arcname` を照合した `題名(作品ID).ext`、`題名(作品ID)_1.ext` … の形式を使う。タイトルが `_数字` で終わる際の配置も原版と一致させる。

ZIPは`ZIP_DEFLATED`で作り、ZIP64を無効化。zip内部のエントリ一覧と全エントリCRCを検査してから、同じ専用root内の一時ファイルを**上書き不可のハードリンク公開**で確定させる。既存ZIP・同じ作者IDの別名ZIPがある場合、原版のように改名/追記する代わりに、**安全のため明示的に拒否**する。

## 不変性・故障時の動作

- 旧PixivVaultのDB・画像・ZIP・設定・Cookieは一切変更せず、元管理rootの世代や旧receiptも書き換えない。実Pixivへの新しい通信は発生しない。
- ZIP作成はUIスレッドではなく`asyncio.to_thread`で行い、生成中の画像ページは各ページのSHAとreceiptを再照合する。最終公開前にも、作成開始時のアクティブ世代が変わっていないことを確認する。
- 初回は存在しない専用rootのみを受け入れる。アプリ固有の正しいmarkerがある既存rootを再利用可能。未知の既存ディレクトリは拒否し、誤った場所へ勝手に書き込まない。
- ZIP書込・CRC検証・リンク公開が失敗した場合は完成ZIPを作らず、一時ファイルを削除する。OS障害で残った一時ファイルは`/.incomplete/`に隔離され、表示・再利用しない。
- 次の起動時に、アプリ固有の一時ZIP名・通常ファイル・link数1〜2であることを確認し、未完了の一時リンクだけを削除する。公開直後のクラッシュで同一inodeの公開ZIPと一時リンクが残った場合も、公開ZIPは保持し、不要なリンクだけ除去する。未知の一時ファイルやシンボリックリンクがある場合は起動を拒否して保護する。
- 複数clientが同時に出力する場合はアプリ単位の1 writerロックで直列化せず2件目を拒否する。アプリ終了は実行中writerの終了を待ち、元画像readerを途中で閉じない。
- **専用ZIP rootは1つのアプリプロセス専有とする。** 別プロセスから同じrootを同時使用することは未対応。別プロセスが起動して一時ZIPを復旧しようとすると、そのプロセスがまだ書き込み中の一時ファイルと競合する可能性があるため、二重起動しない。
- 通常のアプリ終了はUIループ外で処理し、書き出し中に終了する場合は各ページの境界で中断して一時ZIPを削除する。公開済みZIPは保持する。コピー先はNTFS等、同一ボリューム内の通常ファイルハードリンクをサポートするファイルシステムが必要。
- 表示作者やタブが変わった後に届く古い完了通知は捨てる。表示中の選択状態はclient単位で分離する。

## 未達と制限

これは**既存管理画像の非破壊ZIP書き出し**の完成であり、旧アプリ全機能の移植完了ではない。

- 1作者あたり3000作品・5000画像・入力総容量1.7GiBを上限とし、巨大作者のZIP64出力や分割ZIPはまだ対応しない。最大容量・多数作者のp95/メモリ改善率は実測なし。
- 元のZIPへの追記、作者名変更時の既存ZIP改名、元画像の削除、旧DBへの保存反映は**意図的に実装しない**。管理rootと旧資産を保護する上位制約を優先する。
- 新たな管理保存画像そのものの命名と保存構造は引き続きreceipt＋世代管理を使用し、原版フォルダへ直接書き戻さない。
- ZIPの原版読み込み/IDレス旧名の曖昧性検出は既存ReadOnlyLocalMediaCatalogを維持。既存読取機能の再実装をしない。
- 実Cookie/実画像ZIPの受入はまだ行わず、合成Edge・Windows配布・故障注入で独立検証する。
