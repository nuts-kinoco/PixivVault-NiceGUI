## 計測と通信上限

- 各操作は同じ Chromium ビューポートで時間帯を揃え、各 20 回を目標に元→移植と移植→元を交互にして各 10 回以上を採る。各版の準備・ウォームアップ・計測を識別する。ランキングは初回画像ロードとウォーム状態の再取得を区別し、全画像を各試行で再取得しない。画像は表示経路で必要なものに限る。初回のカード構築が可視範囲外も取得する場合、同条件で可視範囲を限定できる計測方法を明記する。
- 入力から対象結果が画面へ描画されるまでを主指標にする。API の HTTP 開始から本文受信終了、対象画像の開始から受信終了を記録する。並行の待ちは重複計上しない。ペース待ち、レスポンス後の処理、UI 反映・画像デコードを区別し、クリティカルパスを同定できない場合の残差はアプリ CPU 時間と呼ばない。中央値と nearest-rank p95 を算出し、成功件数と中断理由も添える。
- 起動・確認・ウォームアップ・再試行も含め **全操作・両版合計 180 件**。GET の開始間隔は共有で 0.875 秒以上（最大約 1.143 req/s）。Pixiv の対象読み取り経路と画像 CDN のみを許し、書き込み、リダイレクト、自動ダウンロード、ブラウザー Cookie 抽出は遮断する。移植版は製品の取得停止ゲートを経由する。バックグラウンドの取得を実行する設定・入口は使わない。
- 429、403、認証の不成立、CAPTCHA を確認した時点で共通の停止状態を記録し、後続 GET を拒否する。移植側に停止状態がある場合も共通計測を止める。拒否後に別アカウントや別経路で再試行しない。アカウントが確認できない場合は読み取りの事前確認を越えない。
- 試験用所有者を使う前に、[既存の起動手順](TEST_OWNER_LAUNCH.md#L6) に従い、通常製品側の読み取り専用表示で Windows ユーザー共通の取得停止状態を確認する。複製のローカルゲートだけを読んだ結果は、共通ゲートの状態確認には使えない。
- 証拠は数値、操作区分、固定エラー分類、候補 SHA、プロセスの起動・終了記録に限定する。URL、本文、アカウント識別子、Cookie、トークン、パスワード、生画面は残さない。所有するプロセスだけを終了し、残存を確認する。
