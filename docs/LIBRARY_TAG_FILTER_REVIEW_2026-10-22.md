# ライブラリのタグ条件移植

最終目標はPixivVault全体の移植完了。この実装は段階4の中の限定マイルストーンであり、段階4・製品全体の完了ではない。原版、本番SQLite、実画像、Cookieは変更しない。

## 基準と操作契約

基準は読取統合 `97efc035ca5096b8c135d69f86d49c93435ae5cd`。原版 `library_tab.py:497-553,667-689,1758-1775,2644-2736,2938-2974` と `database.normalize_tag` を静的照合した。

- タグはNFKC・前後空白除去・ASCII英字の小文字化で正規化。含む条件は既定AND、切替でOR。除外条件のいずれかに一致した作品は除く。
- テキストとタグの両方に**同じ作品**が一致したときだけ作者を表示する。別々の作品に条件が分散していても一致にしない。
- 作者代表・作品数・作者詳細は全作品から算出する。詳細の50件追加、全ページ、ビューア、戻りを維持。
- 既定閉・幅280pxの押し出しパネルと8席を維持。タグ欄は原版どおり固有項目。未移植の日付等に操作部品を置かず、原版に存在しない種別・作者件数フィルタを新設しない。
- タグ条件はDL済みとマイブックマークで共有し、クライアント間は独立。絞り込み後もブックマークの選択を維持。パネルを閉じても適用中の条件を外側のチップから解除できる。

## 独立レビューと修正

純粋モデルは別担当が実装し、UI接続は統合担当が実装。第三者レビューでは、常設の追加・解除・AND/ORボタンが再訪後に古いイベントを受理できる問題を指摘した。

修正ではNiceGUI公開 `Element.on(js_handler=...)` を使い、ブラウザでクリック/Enterが起きた時点の画面世代を送信して、サーバー側の現在世代と照合する。チップは構築時のobject identityも検証。タブ離脱・再訪・再読込・サブビュー変更後の旧イベントを拒否し、クライアント削除ではUIを再生成しない。修正版の独立静的判定はAPPROVE。

## 失敗試行と未確定ゲート

Edge初回はチップ解除の描画完了前に旧作者カードを押す検証競合、2回目は作者詳細の背後で隠れた絞込ボタンを押す検証手順の誤りで失敗。世代ガードは弱めず、描画世代待ち・作者一覧への復帰を明示して最終走で合格した。

合成transport最初の最終走は全操作成功後の終了待ちでタイムアウト。終了要求のためだけに新たな一覧ページと大量の画像要求を生成していた検証器を、UIを閉じた後のrequest-only終了要求へ変更した。`live-final-02`では正常終了を確認し、強制cleanupは使っていない。旧失敗結果は保持。

Windows `native-final/native.json` はタグ操作・通常終了まで成功したが、GDI baselineで総合FAIL。`native-diag-02/native.json`にclient矩形 `(496,536,3832,2362)` と仮想画面 `(0,-1080,6000,2160)` を記録し、下端202pxが画面外であることを確認した。旧失敗試行はそのまま保持する。

検証器へ明示オプション `--client-origin 100 140` を追加。検証前にroot/topのPID・作成時刻・所属を確認し、同じmonitor/DPI/寸法を維持して専用top HWNDだけを移動する（SWP_NOSIZE/NOZORDER/NOACTIVATE）。WebView子は移動せず、復帰中は位置を補正しない。従来の画面内・全sample owner・同寸法/DPI・安定2標本・画素差の合格条件は変更していない。配置や検証が失敗しても通常WM_CLOSEの経路を維持する。

配置補助の独立レビューでは、配置例外を記録しても総合判定が他の条件だけでPASSになり得る漏れを検出した。既存mainフルフローの故障注入で1 failed/3 passedとして再現し、全errorsが空であることと、配置指定時のexplicit_setup成功を総合合格条件へ追加。通常WM_CLOSE経路は維持した。修正版を独立再レビューしてAPPROVE、全545pytestと同一コピーexeの `native-positioned-04` を再実行し合格した。

**製品の既定起動位置が常に画面内に収まることは未解決**であり、移植全体のWindows受入残件とする。head/main CIも、この限定ネイティブ結果とは別ゲートで確認する。
