# 試験環境限定の共有STOP所有者

ソース検証用の入口は `tools/launch_test_owner.py`。通常の `python -m pixivvault_nicegui` に所有者切替引数・環境変数・保存設定は追加しない。配布済み実行形式では試験コンテキストを拒否する。

1. 候補内で専用Pythonを使い、`tools/launch_test_owner.py --init-workspace <新規の絶対パス>` を実行する。既存ディレクトリは初期化できない。
2. 実Cookieを置く前に、通常の製品経路の読み取り専用表示で実ユーザー側の所有者がSTOP中でないことを確認する。STOP中または確認できないときは、実Cookieを試験領域に置かない。Cookieが必要な別工程では、コピーを `<試験領域>/credentials/cookies.txt` に置く。プロフィールは `<試験領域>/profile`、保存先は `<試験領域>/storage` に分離する。今回の工程では実Cookieを使用していない。
3. `tools/launch_test_owner.py --test-workspace <試験領域> -- --native --profile-root <試験領域>/profile --port <試験ポート>` で起動する。初回設定・移行前は認証通信を開始しない既存の復旧画面になる。
4. 起動検査の案内または設定画面から正式移行を開き、試験保存元をすべて列挙してプレビュー・明示確認する。移行先は `<試験領域>/shared-stop-owner`。既存のロック・コピー・SHA/状態検証・原本保全・切替をそのまま用いる。
5. 同じ試験ツール・試験領域で再起動する。試験所有者は実ユーザーのSTOPを引き継がない。所有者の自動作成はせず、移行が作成した所有者を同じ検証で開く。通常CLIでこのプロフィールを開くと試験所有者へは切り替わらない。

指定の入口はソース用の試験ツールに限定する。試験領域のマーカーはアクセス権限の証明ではなく、試験用入力の取り違え防止である。コードを変更できる者に対する保護とは主張しない。

パスは絶対パス・リンク拒否・試験領域配下を必須とする。Cookieを含むCLIの全Path入力、プロフィールから解決したPath、正式移行の追加保存元を検証する。外部URI・ブラウザー拡張の受信は試験入口で拒否する。コーデックPythonなどのPathも領域内に限定される。

空の所有者は作らない。移行で照合した保存元だけが履歴の根拠であり、履歴がないことを過去すべての履歴を引き継いだ事実へ置き換えない。停止履歴や所有者同一性の検証・通信拒否は共通実装を用いる。

上のNative UI手順の実画面・実API確認は別工程。本工程は生成したプロフィール・停止履歴だけで検証する。
