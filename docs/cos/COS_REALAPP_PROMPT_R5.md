あなたは、Windows 上の PixivVault（NiceGUI 版・開発中）の「実機の画面確認」だけを担当します。コードの修正・テストの実行・設定の変更はしません。結果は表で返します。今回は、前回（R4）で FAIL だった項目の再確認と、最新の修正の短い確認だけです。**R4 で PASS だった項目は再確認しません。**

## 前提
- アプリは Claude Code 側で起動済みです。**あなたは起動・再起動しません**。`http://127.0.0.1:22386/` が応答しない場合や、「PixivVault — 起動設定の確認」「STOP保護または設定の保存状態を確認できません」の画面が出る場合は、確認を始めず、その画面の文言を報告して終了します。
- 画面は `http://127.0.0.1:22386/` を開いて確認します。ウィンドウ幅は 1280×800 と 1920×1080 の 2 通りで見ます。
- スクリーンショットは `S:\Projects\PV-DEV-20261117\verify\cos_<日付>_R5\` に保存します（C ドライブには保存しません）。認証 ID・アカウント ID・Cookie の値・作品の画像が写らないように加工してから保存します。既存の R4 の証拠は削除・上書きしません。
- 借用プレミアムは ON のままです（OFF にしない）。

## してはいけないこと
- 設定の保存・変更、借用プレミアムの ON/OFF、パスワード・Cookie・トークンの入力、ファイルの削除、「ごみ箱を空にする」「削除」「取得停止の回復」「正式移行を実行する」などの不可逆な操作。
- **ダウンロードの実行・定期チェックの今すぐ実行・☆の保存・フォロー同期・ランキングの取得（「取得・更新」）は押しません**（実通信と保存が起きるため）。表示と、開閉・並び替え・切替のような表示だけの操作にとどめます。
- 迷ったら押さずに、その状態を報告します。
- 例外: ヘッダーの「ライト/ダーク切替」は、テーマ確認のために押してかまいません。確認後は最初のテーマに戻します。

## 確認項目（各項目に PASS / FAIL / 判定不能 と、見たままの文言を記録）
**判定不能にするときは、「何が足りなかったか」を 1 行で書きます。**

A. R4 の FAIL の再確認
 A1（C5/D2）. 次の見出しが**明朝体**（Yu Mincho 系）で表示されている。本文はゴシック（Noto Sans JP 系）のまま。見たままの書体名（DOM で確認できる場合は font-family）を記録する。
  - 重複整理: 「重複候補の確認」
  - キュー: 「現在のジョブ（アプリ連携）」と「ダウンロードキューログ」
  - 設定ダイアログ（変更・保存しない）: グループ見出し「エクスポート」
  - 設定ダイアログの題（前回と同じく明朝のまま）
 A2（A2）. 定期チェック画面の「対象アカウント ID …（未紐づけ）」は、**現在ログイン中のアカウント自身の ID の表示で、仕様どおり**と判断済み。表示が出ていることだけを確認し、ID は書かない。別アカウントのものでないこと（ヘッダーの認証ラベルと同じ人のもの）を、見て明らかに違う場合のみ報告する。

B. 最新の修正の確認
 B1. ヘッダー（上部）の「アプリ: 受信待機中／未接続」という丸印付きの表示が**無い**。「API切り替え」のスイッチは残っている。
 B2. 共有の取得状態（ヘッダーの下の文言）に「HTTP 404: 試行 1/3で取得を終了しました。」が、**各タブを一巡して眺めても出ない**。出た場合は、直前に触ったタブと操作、表示された文言を書く（取得は起こさない）。あわせて、**確認を始めた直後**と**10 分ほど後**に、ヘッダーの下に「取得または待機を中止しました…」「[通信停止中] …」のような文言が出ていないかを記録する（起動直後は処理が終わるまで一時的に出ることがある。出ていた場合は、何分後に消えたかを書く）。
 B3. マイブックマーク: 検索欄に存在しない語を入れて 0 件にしたとき、「保存済みのブックマークを表示しています」と出ず、0 件の案内（「条件に合うブックマークがありません」など）になる。確認後は検索欄を空に戻す。
 B4. 自分のランキング（個人ランキング）に切り替えて、赤いエラーや空白だけの画面が出ない（取得はしない）。結果が既に表示されている場合は、カードの右クリックメニューから「出さない一覧」を開いて閉じる（何も隠さない・押すのは開く・閉じるだけ）。開けない・エラーになる場合は文言を書く。

## 報告の形式
1. 表（項目 ID / 結果 / 見たままの文言 / 保存した画面のファイル名）。
2. FAIL・判定不能は、再現手順と画面を 1 つずつ。
3. 気づいた違和感（元の参照画像と明らかに違う点、操作が重い・固まる、エラーメッセージ）。
4. 実行した操作の一覧（押したボタン、テーマの切り替えと戻した時刻）。

## 完了時の出力（必須）
すべての確認が終わったら、最後に次の 2 つを、この順で出力して終了します。
1. 合言葉の行: `合言葉: 紺碧の風見鶏-R5-2093`（この文字列を一字も変えない。全項目を確認し終えるまでは出さない。途中で止まる場合は出さず、止まった理由と未了の項目を書く）
2. 「Claude Code への返信」ブロック。次の形のコードブロック 1 つにまとめる。

```
[COS → Claude Code 返信 R5]
合言葉: 紺碧の風見鶏-R5-2093
実施日時: <開始〜終了>
結果: PASS <n> / FAIL <n> / 判定不能 <n>
FAIL・判定不能の項目: <ID と 1 行の要点>（無ければ「なし」）
画面の保存先: S:\Projects\PV-DEV-20261117\verify\cos_<日付>_R5\
実行した操作: <押したボタン・テーマの切り替えと戻した確認>
気づいた違和感: <箇条書き。無ければ「なし」>
未了の項目: <無ければ「なし」>
Claude Code にしてほしいこと: 上記の FAIL・違和感を修正し、修正後に R5 の該当項目だけ再確認用のプロンプトを出す
```
