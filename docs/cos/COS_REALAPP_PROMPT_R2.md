あなたは、Windows 上の PixivVault（NiceGUI 版・開発中）の「実機の画面確認」だけを担当します。コードの修正・テストの実行・設定の変更はしません。結果は表で返します。今回は、共通シェル（ヘッダー・タブ・配色）を元アプリ（Flet 版）の見た目に合わせた変更の確認です。

## 前提
- アプリは Claude Code 側で起動済みです。**あなたは起動・再起動しません**。`http://127.0.0.1:22386/` が応答しない、または「PixivVault — 起動設定の確認」「STOP保護または設定の保存状態を確認できません」が出る場合は、何も押さずに状態を報告して止まります（合言葉は出さない）。
- 画面は `http://127.0.0.1:22386/` を開いて確認します。ウィンドウ幅は 1280×800 と 1920×1080 の 2 通りで見ます。
- スクリーンショットは `S:\Projects\PV-DEV-20261117\verify\cos_<日付>_R2\` に保存します（C ドライブには保存しません）。書けない場合は、その旨を報告し、本文に見たままの文言を書きます。
- 元アプリの参照画像: `S:\Projects\PV-DEV-20261117\verify\original_20261117_225445\`（`<幅>x<高さ>_<dark|light>_<画面>.png`）。共通シェルの比較表は `S:\Projects\PV-DEV-20261117\verify\shell_20261117_final\comparison.md` と、同じフォルダーの画像（`orig_*` が元、`1920x1080_dark.png` などが製品）。

## してはいけないこと
- 設定の保存・変更、借用プレミアムの ON/OFF の切り替え、パスワードや Cookie・トークンの入力、ファイルの削除、「ごみ箱を空にする」「削除」「取得停止の回復」「正式移行を実行する」などの不可逆な操作は押しません（ダイアログを開くのは可、実行は不可）。
- Cookie の値・アカウント ID・作品の画像が大きく写る画面のスクリーンショットは撮りません（撮る場合は、その部分を切り取る）。
- 迷ったら押さずに、その状態を報告します。
- 例外: ヘッダーの「ライト/ダーク切替」ボタンは、テーマ確認のために押してよいです。確認後は、最初のテーマに戻します。

## 確認項目（各項目に PASS / FAIL / 判定不能 と、見たままの文言を記録）
A. 起動直後
 A1. 最上段に赤字「⚠️⚠️ 本番DBを使用中: <パス>」。
 A2. 認証ラベル「● [有効] ログイン中 (有効期限 残り約N日) - ユーザーID: …」（ID は報告に書かない。「表示あり」とだけ書く）。
 A3. 起動直後のタブが「ダウンロード」。
B. ヘッダー（元の画像と並べて見る）
 B1. 左に大きな「PixivVault」、その下に認証ラベル、その下に接続行（「アプリ: …」の表示と「API切り替え」のスイッチ）がある。
 B2. 右上にアイコンボタンが 6 個、左から: 直近のバックアップ（時計の矢印）、閲覧履歴（目）、保存フォルダ（フォルダー）、テーマ（太陽/月）、ブラウザで Pixiv を開く（地球）、設定（歯車）。
 B3. 「直近のバックアップ」アイコンを押すとバックアップ画面が開く。「閲覧履歴」を押すと履歴のダイアログが開く（閉じる）。
 B4. 元の画像と比べて、ロゴの大きさ・位置、アイコンの位置が明らかに違う場合は書く。
C. タブ
 C1. 並び（左から）: ダウンロード、キュー、失敗リスト、重複整理、学習、ランキング、自分のランキング、ライブラリ、おすすめ、定期チェック、メタデータ補完。違えば実際の並びを書く。
 C2. 全タブが同じ幅で、アイコンが付いている。
 C3. 1920×1080: 11 個が 1 行に収まる。1280×800: 2 段に折り返し、全タブが画面内に見える（横スクロールバーが出ない）。
 C4. 選択中のタブは薄い青の地になっている。
 C5. 「直近のバックアップ」は、タブではなくヘッダーのアイコンにだけある。
D. テーマ
 D1. テーマボタンでライトにする。地が明るく、カードも明るく、文字が読める（暗いカードがライトの地に残っていたら FAIL）。
 D2. 設定ダイアログを開き（変更しない）、ライトで文字が読める。閉じる。
 D3. ダークに戻す（最初のテーマに戻す）。
E. 全画面（開くだけ）
 E1. 12 画面（ダウンロード、キュー、失敗リスト、重複整理、学習、ランキング、自分のランキング、ライブラリ、おすすめ、定期チェック、メタデータ補完、直近のバックアップ）を順に開き、赤いエラーや空白だけの画面がない。
 E2. ダウンロード画面は、元の画像（2 カラム: 左=作者一覧、右=この回の対象と実行ボタン）と構成がまだ違う（既知。今回は復元の対象外）。違いを 1〜2 行で書く。
F. 前回（R1）の確認の再確認
 F1. ライブラリ: 作者カード「torino」にサムネイルが出る。ブクマ数の下限 1,000 → 8,000 → 条件をクリア、で 1 → 0 → 1 作者になる。
 F2. 重複整理のごみ箱ダイアログを開く（実行しない）。上から、タイトル、警告 1 行、件数入力、「閉じる」「空にする」。入力が空のとき「空にする」は押せない。

## 報告の形式
1. 表（項目 ID / 結果 / 見たままの文言 / 保存した画面のファイル名）。
2. FAIL・判定不能は、再現手順と画面を 1 つずつ。
3. 気づいた違和感（元の参照画像と明らかに違う点、操作が重い・固まる、エラーメッセージ）。
4. 実行した操作の一覧（押したボタン、テーマの切り替えと戻した時刻）。

## 完了時の出力（必須）
すべての確認が終わったら、最後に次の 2 つを、この順で出力して終了します。
1. 合言葉の行: `合言葉: 紫の羅針盤-R2-7305`（この文字列を一字も変えない。全項目を確認し終えるまでは出さない。途中で止まる場合は出さず、止まった理由と未了の項目を書く）
2. 「Claude Code への返信」ブロック。次の形のコードブロック 1 つにまとめる。

```
[COS → Claude Code 返信 R2]
合言葉: 紫の羅針盤-R2-7305
実施日時: <開始〜終了>
結果: PASS <n> / FAIL <n> / 判定不能 <n>
FAIL・判定不能の項目: <ID と 1 行の要点>（無ければ「なし」）
画面の保存先: S:\Projects\PV-DEV-20261117\verify\cos_<日付>_R2\
実行した操作: <押したボタン・テーマの切り替えと戻した確認>
気づいた違和感: <箇条書き。無ければ「なし」>
未了の項目: <無ければ「なし」>
Claude Code にしてほしいこと: 上記の FAIL・違和感を修正し、修正後に R2 の該当項目だけ再確認用のプロンプトを出す
```
