## 試験の条件

- 観点は美観、元 Flet に対する機能・見た目の退行、Apple HIG 準拠。元・移植版の候補 SHA、プロファイル種別、Windows とブラウザー／WebView、フォント、物理領域と実効 CSS px、OS 倍率とページズーム、テーマを記録する。HIG は適用する原則を引用し、数値合否は PV の A1〜A17 を使う。 [Apple HIG](https://developer.apple.com/jp/design/human-interface-guidelines/) · [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)
- 実機では画面の閲覧と安全と確認されたナビ、開閉、フォーカス移動だけ。実データの書込・削除、認証操作、外部通信、OS 設定変更は行わない。通信や書込を伴う画面、エラー・遅延・破壊的操作・倍率変更は、監督が用意した偽クライアント、隔離ブラウザーまたは証拠で確認する。実ブラウザー・ネイティブ窓・物理操作の証拠は環境ごとに区別する。
- 指定された S: の保存先を使い、資格情報、アカウント・作品の識別値、個人パス、実画像を保存前に伏せる。読み上げが利用できない場合はアクセシビリティツリーで名前・ロール等を記録し、実読み上げは判定不能にする。画像だけで数値、フォーカス順、通知の読み上げを合格にしない。

## 画面 × 条件の実施表

サイズ 2 種（1280×800／1920×1080 の 100%）× ライト・ダーク × 状態 5 種の **各画面 20 セル**を作る。下表の 1 ID に複数の画面・入口・ダイアログがある場合は枝番を振り、各入口を独立した行にする。例えば `U-S15.2/1280x800/100/ライト/長文`。画面ごとに試験用データを揃え、モーダルは実際の起点から開く。メニューやトーストはホスト画面の状態と組み合わせ、成立しない状態には理由を書く。

| 状態 | 作り方（実機で作れない状態は隔離で） |
| --- | --- |
| 通常 | 正常に到達し、代表データ・通常の操作・現在地・関連ダイアログを撮る。選択、無効、hover、フォーカスも採る。 |
| 空 | 初回未取得、実データ 0、検索一致 0 を可能な箇所で区別。未取得なら次に何をできるかを確認。 |
| 長文 | 長い題名・作者名・場所・DB 警告・設定説明・失敗理由・日本語混在・長いタグを入れ、折返しと全文への到達を確認。 |
| エラー | 入口がある画面の偽失敗、欠損画像、権限、拒否、429、保存未確認を個別に用意。実機へ障害を起こさない。 |
| 読み込み中 | 応答を遅らせ、表示直後・待機中・確定後を撮る。処理中の連打防止、旧結果保持、次の行動、通知フォーカスを記録。 |

すべてのセルで UI の階層・余白・整列・色・書体・密度・画像面積・状態と色以外の手がかり・コントラスト・クリック範囲・フォーカス・キー到達・読み上げ名・見切れを確認する。数値は下の A 項目で判定し、開閉や書込などが該当しない項目は理由を付ける。成立する状態の準備不足は判定不能。状態自体が定義されない場合に限り「非該当」とし、例えば「日付選択に行一覧の空データはない」のように説明する。隔離データが足りない状態を非該当にしない。
