# ブックマーク更新の安全契約 — 段階5の限定マイルストーン

対象: `src/pixivvault_nicegui/bookmark_write_evidence.py` と
`tests/test_bookmark_write_evidence.py`。基準mainはPR #17統合後の
`70922d9add8d0f1fee7affe69560209540c16b29`。

## 実pixiv APIの限定受入（2026-10-22）

本人が実Cookieを使ったブックマークON/OFFと実API呼出を明示的に承認した。
既存リポジトリのCookieを**Git管理外**の専用プロセスへ複製し、
トップページの`__NEXT_DATA__`内のログイン済フラグ、正のユーザーID、
CSRFトークンを照合した。値・認証情報・レスポンス本文・実作品IDは記録しない。
旧PixivVaultのDBや画像、Cookie原本は変更していない。

対象は公開作品の**元々未ブックマークの1件**。非公開登録（restrict=1）を
POSTで1回行い、HTTP 200とAPI `error:false` および返却された作成IDを確認。
別のGETで同じIDを確認してから解除をPOSTで1回行い、HTTP 200・API成功を確認。
最終GETで未ブックマークへ戻った。GETは計5回、POSTは計2回、
経過約8.8秒、Cookie前後ハッシュ一致。初期/最終状態はともに未登録、
手動復旧必要フラグはfalse。**同作品に試行を繰り返していない。**

実行記録はignoredの`artifacts/real-bookmark-probe-20261022/roundtrip-result-20261022.json`に
数値・状態だけ保存した。試験用Cookie複製は結果確認後に削除済みで、
元ファイルの残存も確認した。この実測は限定した通信経路の受入であり、
NiceGUI画面からのブックマーク変更や他作品・小説のAPIの成功を意味しない。

## コードレビューで閉じた危険

- 追加HTTP成功でもAPI `error` がtrueなら成功にしない。レスポンス内IDの
  欠落・不正・複数異値は削除の認可証拠にしない。
- 追加前に既存のブックマークがあるなら、そのIDを削除対象にしない。
  追加レスポンスの作成IDと再取得のIDが一致した場合だけ補償解除を認める。
- 解除のHTTP/API応答が失敗・未確認なら、最終GETが未登録でも
  「API更新の往復が完全成功した」とは判定しない。
  最終GETが失敗/不明、またはブックマークが残るときは手動注意を要求する。
- 純粋な新規モジュールは通信、Cookie、DBやファイルI/Oを一切実行しない。
  実アカウントを書き換えるメソッドはこのPRに含めない。

## 検証・残ゲート

本モジュール専用36 pytest成功、PR #17統合後の全pytestは556成功
（既存依存の非致命的警告1件）。コードの独立レビューとCIは別の受入ゲート。
今後、利用者画面でのON/OFFを有効化する前に、ユーザー操作からの明示的な
承認・保存先同期・二重操作拒否・通信失敗の再読取・競合時停止・
元のブクマ属性（公開/非公開・タグ・コメント）保持を確認する。

実際のPixiv APIには旧コード上で未検証と記された削除仕様がある。
今回の1件の成功は同じAPI形式で別作品/別時点の成功を保証しない。
サーバー側の競合は読取→解除の間に発生し得るため、識別子照合だけで
TOCTOU競合を完全に消せるとは主張しない。
