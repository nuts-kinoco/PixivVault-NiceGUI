# 表示・回復バッチ（2026-11-10）

対象は429の待機・再試行、画像取得失敗の代替表示、中断した保存の後片付けと表示、重複スキャンの警告と進捗。

## 429と通信エラー
設定の `api_retry_count` は初回を含む総試行回数（1/3/5/10）。429の待機は `api_retry_wait`（3/5/10/30秒、既定5秒）。通信エラー・一時的なHTTPエラーは従来の指数待機とジッター。画面上部に試行回数・待機理由・残り秒数を表示する。操作の制限時間とキャンセルを優先し、無制限に再送しない。

新たに受信する429は、GET再試行ポリシーが管理する間は共有STOPへ永続化しない。上限到達時は元のHTTP例外を返し、この起動中は同じポリシーを共有する取得を止める。再起動でメモリ内の停止が消える。401/403と所有者検証・不確かな送信結果の保護は維持する。過去に永続化されたSTOP記録は自動で変更・消去しない。借用アカウントのクォータ処理とPOST操作は変更しない。

## 画像と中断した保存
取得できなかったサムネイルには画像アイコンと「画像を取得できませんでした」を表示する。通信混雑の解消後に画面を再表示する案内も出す。

保存の作業用フォルダーには、同じ管理領域内にジョブ・作品を対応付ける所有記録を付ける。再試行が完了し保存証拠を検証した後、そのジョブ・作品に一致する作業用フォルダーだけを片付ける。完成したoutputs/generations、別ジョブ、未知のファイル、リンク、対応付けのない旧作業フォルダーは削除しない。

再起動後のキュー・失敗一覧には中断の原因と記録済みの保存ページ数を表示する。「途中データ・保存未完了」と明示し、完成保存とは区別する。表示する数値は中断前に永続化された進捗であり、未記録のページ数を推測しない。

## 重複スキャン
2000枚を超えた作者は従来どおり比較を省略し、作者IDと対象枚数を画面に列挙する。保存ページの検証・旧保存画像の照合・作者別の特徴計算・比較・最終照合の段階と件数を表示する。全件数が未確定の段階は不定進捗、件数が分かる段階はその段階の分母を使う。全体の推定残り時間や偽の百分率は表示しない。
