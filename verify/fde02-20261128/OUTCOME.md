## 2. 変更

- 旧物理隔離で確定した unit を、管理領域と区別して復元一覧に表示する。復元後は除外を解除し、スキャンを無効化してライブラリを更新する。

- フォルダ画像は Windows の上書き不可の rename で配置する。ZIP は現在の物理 ZIP と一覧用 ZIP の両方を検査し、必要なページだけを追加する。元の世代と一致するときは隔離前 ZIP をそのまま使う。置換直前の ZIP は別名で退避し、復元に成功した後も保持する。
- 復元 intent を既存の物理隔離ジャーナル領域に記録し、復元先の配置と照合が済んでから `CURRENT` を公開する。復旧は既存入口で実行する。競合が未解決の保存元は利用を止め、別の旧ライブラリ書き込みによる revision 更新も止める。隔離コピーの削除方法・対象は従来の処理を使う。

## 4. 未達・依存・残るリスク

- Sol が保存領域、索引、ジャーナルの変更を独立に静的検証した。復旧時の衝突の扱い、証拠とハッシュの再照合、既存画面からの復旧導線を修正した。修正後の再確認では、範囲内の具体的な追加不具合は見つからなかった。Native の実機操作と原受入の判定は担当側に残る。
- 逸脱日誌。最初の回帰試験で 1 failed、184 passed。物理隔離を持たない旧ストアの候補読取りに失敗し、空にする確認まで進まなかった。根拠は一時領域の `regression01.txt`。候補読取りを修正し、最終回帰試験で同ケースが通過した。
- 監督裁定どおり、協調する書き手を writer fence で排他する。非協調の書き手による変更を永続的に禁止する仕組みはない。ZIP を退避するときに現に元の名前で存在したファイルと、復元先に先に現れた第三者のファイルを保全する。
- 既存移動の ZIP 置換では、元の inode のハードリンク作成が失敗した場合も `os.replace` に進む。保存した `before` は照合時点の内容であり、その後に非協調の書き手が差し替えたファイルまでは保全しない。根拠は `legacy_physical_quarantine.py:525` および `:533`。この置換処理は変更していない。
- 容量不足が準備中に発生した場合、配置前で止まる。データを消さないため未公開の準備物や復元後の退避記録は保持する。
- 合成環境で中断例外を注入した。物理的な電源断やネットワークドライブの挙動は未測定。

## NEON 独立レビューへの対応

対象は `aca3ec65` に対する [REVIEW_NEON.md](REVIEW_NEON.md) の High 2 件・Medium 4 件。移動側 `legacy_physical_quarantine.py` は基点と差分なし。

| 番号 | 現物で確かめた結果と対応 |
| --- | --- |
| 1 | 配置後だけ inode が変わる条件で、ファイルの確定と ZIP の中断復旧がどちらも停止した。準備ファイルは inode まで照合し、公開先は同じボリューム・サイズ・SHA-256 を確認する。ハードリンク復元時は退避した元ファイルと同一であることも確認する。試験ボリュームは NTFS。FAT 系の inode 変化は合成した。FAT の ID の扱いは [Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-by_handle_file_information) を参照。 |
| 2 | 低い Zip64 閾値で実際の Zip64 ヘッダーを生成した。Python 3.13.11 の `ZipFile._write_end_record()` は新しい Zip64 情報の追加時に旧情報を除去するため、報告にあった古い中央オフセットによる `BadZipFile` は再現しなかった。`ZipInfo.FileHeader()` が書くローカルヘッダーには古い Zip64 拡張が残って重複した。全メンバーの書込み用メタデータから旧 Zip64 情報を外し、生成後に名前・サイズ・CRC と全データを再読した。実サイズ 4 GB 超は未実行。 |
| 3 | 親フォルダが事前にない場合と、intent 確定直後に消える場合に未完了記録が残った。事前なら拒否し、準備済みで配置前なら取消する。両方で旧ライブラリのごみ箱操作が再び成立することを確認した。 |
| 4 | 作者フォルダとブックマークから同じ画像を参照する合成環境で inode の分断を再現した。退避した元ファイルのハードリンクを優先し、リンク不可時は単一リンクの退避ファイルに限り検証済みコピーを使う。退避ファイルが欠損、改変、または別名を保てない場合は拒否する。旧版の未公開 intent が独立コピーをまだ準備中なら取消し、再実行できる。旧版が別 inode のコピーを既に公開名へ置いた場合は台帳確定を止める。そのコピーを別名で保全して公開名を空けると、既存の復旧操作で取消した後に正しいリンクで再実行できる。同じバイトでも、新規リンク復元後に別 inode が置かれた場合は確定を拒否する。 |
| 5 | ZIP を退避した直後に別ファイルが現れると、次の復旧付き読取りまでブロック通知と候補一覧が古かった。耐久 intent 後に失敗した保存元を直ちに登録し、復旧が必要な候補の再選択を防ぐ。既存の第三者ファイルと退避世代は保持する。 |
| 6 | 未スキャン画面では、復旧ボタン自体を表示しても親パネルが隠れていた。常時表示領域に移し、復旧待ちを検出した新しい画面でも表示する。実際の NiceGUI コントローラで、既存の復旧入口から再開することを確認した。 |
