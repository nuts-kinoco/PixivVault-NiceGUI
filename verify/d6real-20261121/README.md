# D6 実利用速度の計測補助

製品コードの基点は `2ee1860ecc20ea3e6f5d8954740ecae64fd33d87`。対応する計画と中断結果は [計画](../../docs/P6_REAL_USE_PLAN_20261121.md)、[初回事前確認](../../docs/P6_REAL_USE_RESULT_20261121.md)、[継続結果](../../docs/P6_REAL_USE_CONTINUATION_20261121.md) にある。

`preflight.py <S: の複製ディレクトリ>` は、`S:/Work/_tmp/PV/d6real` 配下の `backup-copy` から、保存参照の分類、ローカル停止履歴、コピー内の件数、Cookie のローカル解析結果を JSON にする。通常所有者の状態や認証の有効性は別途確認が必要。出力の `status: blocked` は通信前の診断結果。出力には資格情報、元の保存パス、ID を含めない。

`timing.py <S: の試行 JSON>` は一つの操作・条件を収めた行の配列を受け取り、試行ごとの区間から中央値・nearest-rank p95・有効件数を集計する。行の形式は次のとおり。

```json
{
  "app": "original",
  "pair": 1,
  "operation": "ranking_official",
  "condition": "warm",
  "start_ms": 0,
  "paint_ms": 150,
  "network_ms": [[40, 110]],
  "api_ms": [[40, 90]],
  "image_ms": [[90, 110]],
  "pace_ms": [[25, 40]]
}
```

- pair は 1 から順に並べる。奇数は `original → nice`、偶数は逆。最終組の片側だけの結果は件数に含めない。同日の同じ検索条件・同じ表示範囲は呼出元で照合する。
- 区間は入力から描画までの同一時計系の経過ミリ秒。通信の重なりは和集合で数える。計測のペース待ちは通信区間との重なりを引く。残差はアプリ処理・描画・観測を含む。API・画像の区間と、最後の通信終了から描画までの時間も出す。
- `live_gate.py` の `Ledger` を両版の HTTP 配信直前で共有する。アダプターは宛先を限定し、リダイレクトと測定対象外の自動取得を止める。NiceGUI は製品の共有・プロフィール取得停止ゲートを維持する。
- Flet ソースの準備は既存 D6d runner の `original_copy` を利用する。Cookie の無いソースコピーと、S: の隔離プロファイルを別に準備し、製品の参照先・ゲートを確認できた構成だけを使う。既存の合成 runner は隔離起動と画面観測の参照実装。

## ランキング測定

開始前に [計画の非停止確認](../../docs/P6_REAL_USE_PLAN_20261121.md) を行う。専用 venv の Python で `prepare_live.py <S: の新規実行ディレクトリ> <同一工程の通算済み試行数>` を使い、通常起動の隔離所有者を準備する。既存の停止・成否不明がある実行は保全する。先の試行を通算する引数は最終台帳と照合する。`rank_measure.py <同じ実行ディレクトリ> 10` でループバックの 22830 と 22840 に起動し、10 組の更新と終了記録を取る。実際の STOP／認証失敗／CAPTCHA／403・429 時は手順どおりそこで中断する。

初回の先頭画像が両版で見えた場合は先頭画像までを計時する。片側の画像を確認できない場合は一覧メタデータまでの比較に切り替え、切替を `ranking-outcome.json` に記録する。成否不明後の修正版はオフライン回帰まで確認した。
