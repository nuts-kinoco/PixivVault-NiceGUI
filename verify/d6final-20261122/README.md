# D6 最終測定の補助

この補助は Flet `3ac3aa0d47a64785251593bcb09bb2d5f6df374b` と NiceGUI `af6039b9a6c4e514d233f0ef3b2006aa98343c49` の日間イラストランキングを比較する。Chromium 1280×1000、初回の先頭画像取得をウォームアップとし、更新を Flet→NiceGUI、NiceGUI→Flet の交互で測る。

1. 通常製品を操作できる本人・実機担当が、直前の読み取り専用ヘッダーで非停止を確認し、確認時刻と状態を渡す。停止中・不明なら計測を開始しない。実機には測定担当から接続しない。 [既定の非停止確認](../../docs/P6_REAL_USE_PLAN_20261121.md#L31)
2. `host_check.ps1` で負荷を確認する。他の試験・自動ブラウザー・担当の実行などが重なる場合は最大60分待ち、引き続き重ければ条件を結果へ記録する。前後の CPU 使用率、外部負荷、測定プロセス・ポートの残りを保存する。
3. `S:/Projects/PixivVault-NiceGUI/.venv/Scripts/python.exe -B prepare_live.py <専用一時領域の新規絶対パス> 83 --owner-open-at <本人確認時刻のISO 8601>` で準備する。同じ専用 Python で `rank_measure.py <同じ絶対パス> 20` を実行する。スクリプトパスは本フォルダから指定し、`TEMP`、`TMP`、`TMPDIR` は S: に設定する。実行コードの SHA と結果を書き出す。10ペアが既存の最低件数。
4. 終了後に `host_check.ps1 -RunRoot <同じ絶対パス> -SeenPath <同じ絶対パスの processes-running.json> -EvidencePath <終了記録パス>` で、起動 PID と専用ポートの残存を再確認する。有効ペアの中央値と nearest-rank p95 を `ranking-summary.json` と `ranking-metadata.json` から求め、最短送信間隔と件数を共有台帳で照合する。成果物へは計時と固定の分類・件数・所有プロセスの確認結果だけを複製する。一時領域のプロフィール、ブラウザープロフィール、クライアントデータベースは成果物に含めない。

第2回の実測開始時の承認枠は残り97件。両版合計85件で送信を止め、前回終了から875 ms 以上を空ける。予期しない応答、異常終了、停止や成否不明を記録した実行は、その台帳を保全し、再使用しない。両版とも現行のプロフィール・共有取得停止ゲートと送信台帳を通る。測定対象外の起動後フォロー同期・定期処理・ブラウザー Cookie 抽出を隔離側で無効にし、起動時の本人確認 GET を含めて数える。

`rank_measure.py` は起動と各ペアの直前に負荷を記録し、`--host-wait-until` の時刻まで必要に応じて待つ。起動直前に複製のゲートを読み取り専用で再確認する。終了後は同じ専用 Python で `aggregate_live.py <同じ絶対パス>` を実行すると `r1` に集計を保存する。第2回は51件を使い、残り46件。 [GET 台帳](r1/dispatch-summary.json)
