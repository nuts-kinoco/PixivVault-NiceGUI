## 逸脱と残る作業

| 発見 | 証拠と処置 | 残るリスク |
| --- | --- | --- |
| 同一カタログのカード再生成でサーバーと画像確認が遅い | 同一レコード集合は pin を維持し、キー付き DOM を再利用。no-store のまま。全入替は Vue の差分で反映 | 画像用のレコード集合が変わると pin を取り直す。重複作品が含まれる場合も旧URLを維持する対応は残る |
| 実データの中央値で目標に届かない | API・待機・候補内の残差を分離。カード処理は中央値2.45 ms、残差は274.9 ms | API 区間と描画・観測を伴う残差の追加分析。モード切替と検索は既存のデバウンスも含む |
| おすすめの棚と学習の振り返りは操作契約が異なる | おすすめの作者オーバーレイは共通グリッド。棚本体は12項目・画面内の個別アクション・理由ダイアログ。学習行は取得失敗リトライと保存状態を持つ | 棚の共有メニューと失敗表示、学習行の差分描画は、各世代の操作を維持できる設計を決めてから実施 |
| A2で既存テストの共有ヘルパーが使われていた | 全体試験の収集結果から依存を確認し、NiceGUI メニューのヘルパーを戻した | A3の製品候補で全体回帰を独立実行 |
| 偽 API の短い待機では状態遷移を確実に観測できなかった | 偽 API 待機を全候補150 msにそろえ、取得中をDOMの差分から観測して全4候補を再計測 | この測定は意図的な偽応答待機を含む。実 API と比較するときは通信を別に見る |
| 長パス試験に最小長のフィクスチャ前提がある | S: の短い pytest basetemp で全体試験の該当1件が失敗。長さを満たす分離パスで同じ試験を再実行 | 全体ログと単独再実行はそれぞれの実行条件に適用 |

次はこの候補の独立検証。特に画像カタログの寿命、操作の世代、現行の保存・フォーカス契約を確認する。実 API は今回の10ペアを終了し、新たな測定は別の許可範囲で行う。
