## 逸脱と次の作業

初回 Python red では pytest の別タスクに NiceGUI の slot を引き継げなかった。各試験本体で client の slot に入り、製品未修正時点で5件の挙動失敗を取り直した。初回のブラウザー契約ハーネスは「同じ結果でも epoch が進む」という第2回の期待で停止した。実完了を待ち、同一更新では epoch と DOM の維持、内容が非重複で入れ替わった場合は epoch 更新を検証するようにした。

同一ライブラリ再読込みの短絡経路で、旧エラー表示が残ることを追加で再現した。画像 pin と一覧を維持してエラー表示を更新し、焦点28件を再実行した。旧候補の全体試験は所有 PID を照合して終了し、候補 `0417eff` で最初から実行した。 [再現](red-status.log) [焦点28件](green-status.log) [旧試験の終了](full-first-stop.json)

全体試験の初回完走は3,975件合格・1件失敗。旧試験は同じ描画の直後に世代が進むことを前提としていた。製品はそのまま、同一描画の維持、および実際に順序を変えた後の旧世代拒否と新世代受理を同じ試験で検証するようにした。関連9件は合格。 [旧契約での全体ログ](full-old-contract.log) [更新した契約の試験](ranking-menu-contract.log)

次の承認済み作業は最終候補の独立再検証。世代更新、文脈競合、ライブラリの画像 pin 寿命と未達の速度目標を照合する。実 API は第3回の範囲外。
