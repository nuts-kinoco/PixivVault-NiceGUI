## L1 回復 GET の進捗

修正前は回復 GET の失敗4件がすべて `cancelled` になった。404 では共有レコードが1件残り、500・429 では元の HTTP ステータスが消えた。試験では同じ TLS 接続で初回成功と無応答切断を起こし、新規接続で回復 GET を受けた。 [修正前ログ](red.log)

| 回復結果 | 共有進捗と追加の確認 |
| --- | --- |
| 成功 | レコードを消去 |
| 404 | レコードを消去し、共有ヘッダーの文言は空 |
| 500 | `failed`、HTTP 500、試行 2/3 |
| 通信切断 | `failed`、HTTP ステータスなし、試行 2/3 |
| 429 | `stopped`、HTTP 429、試行 2/3。共有ヘッダーに永続 STOP と表示。両ゲートは即時に429を記録し、後続の GET を遮断 |

回復の試行数、ゲートへの再入場、例外の伝播は実ソケット試験で確認した。通常の429待機と試行上限による共有停止は B3・Z05 回帰で確認した。 [重点回帰](focused.log)
