# 第15回 取得停止通知・縮小版

| 拒否・異常の発生点 | 物理帰属と世代を進める点 |
| --- | --- |
| ローカル・共有のファイル open／バイトロック／SQLite／解錠・close | 対象ゲート。I/O 捕捉の先頭で記録し、分類や型付き変換に先行 |
| 共有番兵の作成・書込み・同期・読取り・除去 | 共有ゲート。I/O 捕捉の先頭または検証拒否の成立点 |
| 通常 GET／公開 CDN、Native 認証・フォロー同期 | 実ゲートの共通入口。共有オーナー拒否と表示用の通知公開を分ける |
| 共有オーナー確認・Shaft の取得、共有付きリーダー構築 | オーナー確認そのものに共有物理ゲートを束縛 |
| 選択 Cookie と所有者検査 | 選択の検査にローカル物理ゲートを束縛。GET 外の構築、更新、明示書込みにも適用 |
| 旧履歴の登録・検査・解放 | 検査を要求するライブ共有ゲートに束縛。既知 STOP と終了異常を維持 |
| 要求された共有オーナーが欠落、他の既知物理経路あり | 確認不能を経路の既知物理ゲートに帰属。未設定の全経路向けには物理 ID を作らない |
| 明示再確認の候補 | 同じ取得許可経路。全候補の成功を要求し、取得拒否・終了異常・拒否世代差を記録 |
| 背景観測 | 記録入口の帰属を切る。実取得を妨げず、読み取り結果だけを表示に渡す |

| 観測と明示再確認の重なり | 対象ごとの処理 |
| --- | --- |
| 観測だけ、または再確認が開始前に完了 | ゲートの通常診断。実在する STOP、放棄番兵、競合を表示 |
| 再確認が先に開始し、観測の途中／後に終了 | 対象の結果を破棄。既存の固定通知を保持 |
| 観測が先で、再確認がロック取得前後／番兵作成前後に割り込む | 開始時と終了時の世代差でその対象だけを破棄 |
| 再確認の開始から終了までが観測の中に入る、または複数確認が入れ子 | 世代差を検出。進行中の件数だけが同じでも破棄 |
| 明示再確認が正常終了し、次周期に観測 | 番兵を残さず、結果不明を新設しない。異常で残った番兵は失敗として扱う |
| 一方の対象だけが重なり、他方に不整合・STOP・結果不明 | 他方の結果と不整合を保持。同じ所有区分でも物理対象を分ける |
| 両スコープ未設定で初回拒否を表示済み | 同一理由・同一所有区分の観測は1件へ集約。別の不足は別件 |


OS 呼出しから Python の捕捉までの境界は、対象キーの I/O 開始・終了を拒否世代と同じ辞書に載せて判定する。通知公開の状態ロック内で同じ一括スナップショットを読み、候補の仮削除後、読者へ解放する前に保留か拒否を検出する。正常な I/O が再確認の間に完了した場合、開始・終了件数の差は残らない。

背景観測は拒否記録を抑止する。共有オーナーの読取りが一度拒否されても、再確認と重なった観測を破棄した結果が実取得の拒否世代を進めることはない。対象ごとに確定した不整合は保持する。
