| 指摘 | 実装と確認 |
| --- | --- |
| 別ポリシー、フォロー同期の登録前拒否、別ポリシーの観測 | 物理 DB・ロックのファイル同一性でキーを共有。別インスタンスの CDN と通知公開を延期したフォロー同期で元通知を保持した。明示再確認が持つ実ロックはプローブ時の持ち主で照合した |
| 状態ロック保持中の並行拒否 | 拒否は通知状態ロックに依存せず、型付き拒否を生成する点で世代を進める。解除候補を状態ロック内で除外してから、一括世代スナップショットで再検証する。世代不一致では閲覧前に元の通知集合へ戻す |
| 初回 Native 認証 | リーダー登録前のゲート拒否でも固定通知を記録し、次の周期で観測した。正式に所有元を復旧した場合は、現行経路の明示成功まで通知を保持する |
| 再確認中の解除不能な終了異常 | 稼働中候補を全て調べ、先頭と後続のどちらで解放が失敗しても、固定通知と再確認不能の理由を残す |
| 第12回 Argon の閉鎖済み兄弟 | 既存回帰で閉鎖済みリーダーを外し、稼働中リーダーで明示解除できることを再確認 |

プロセス内世代は CPython 3.13 の GIL 有効環境で `Counter.update` の標準整数更新と辞書スナップショットを使う。通知の状態ロックと独立し、ファイルへ保存しない。同時にひとつの明示操作から生じた世代加算を識別し、別取得の拒否だけを開始時点の証明に対する割り込みとして扱う。再確認の終了異常は世代に加えて結果集合にも残す。

### 逸脱・残る境界

初回の実装後試験は `1 failed, 29 passed`。フォロー同期では、同じ理由の実拒否を公開すると既存の通知 ID が更新された。再現試験に通知公開保留を加え、世代だけで元通知の削除を防ぐことを最終候補で確認した。初回のカウンタ試作で出た Python の非推奨警告は、標準の整数加算・辞書スナップショットへの切替で除いた。 [初回の実装後ログ](first-green.txt)

独立静的確認で、OS がロック取得を返してから所有情報を登録するまでに、正常な再確認を競合として表示する可能性が指摘された。観測が取得のロックを待たない条件を優先し、この短い境界を保守的に扱う。別ハンドルが解錠後に取得した競合は隠れない。 [境界の棚卸し](SWEEP.md)

Dots M02 の送信後・応答開始前の既存 GET 再試行・番兵条件は本人裁定の範囲。 [基点の記録](../r11/baseline-m02.txt)
