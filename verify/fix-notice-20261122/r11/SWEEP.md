# 第11回 取得停止と解除の証拠

作業基点 25ddea25。既存の受入では、上限までの bounded GET の 429 は待機・再試行し、上限または終了異常時に同じポリシーを停止する。再起動で解除される停止と、401／403 や単発回復等の永続 STOP の範囲を維持する。

## 送信判定とバイト送信の間

| 区間 | 基点の処理 | 修正で保証すること |
| --- | --- | --- |
| 429 消費から番兵の終了まで | 429 を戻し、bounded GET では番兵を片付ける | 既知の上限・即停止・既知の終了異常を、保護下で同一ポリシーの停止世代へ記録する |
| 番兵・共有／ローカルロックの close・unlock | 異常を一次例外に付け、呼出元で停止する | 異常を付けた一次 429 を、同じプロセスの次の取得を通す前に記録する |
| 選択済み旧履歴の close | 現行のロックを離れた後、旧履歴の byte unlock と close を行う | bounded GET では旧履歴を先に取得する順序を保ち、現行ゲートのプロセス内排他を旧 close の判定まで維持する。競合した取得は許可しない |
| 単発の新規接続回復で 429 | 既存の永続 STOP 経路 | ゲートによる永続 STOP と共有番兵をそのまま使う。bounded のプロセス内ラッチへの置換はしない |
| 発行間隔・取得許可・接続確立・バイト組立 | 発行枠と取得ゲートを通過し、TLS と標準 HTTP の処理を行う | 待ちの後に既存の停止チェックを維持。HTTP の監査イベントをバイトの最終照合より前に置く |
| 監査イベントから sendall | 基点は停止確認 → 標準ライブラリの監査イベント → sendall | 監査イベント → 停止世代の照合 → バインド済み sendall の呼出し。I/O 全体に停止状態のロックを持たない |
| 最終判断を通過した後 | — | ポリシーの RLock 解放、世代照合とチェックポイントからの復帰、準備済みメソッドとデータのロード、sendall の呼出しが残る。TLS 実装内部の処理は呼出し後に始まる。接続・HTTP データ組立・監査コールバックはこの区間の前。最終判定を通過した処理は実行中として扱い、停止状態ロックは sendall に持ち込まない |

## 解除証拠

| 異常・観測 | 解除に使える証拠 | 否定できないとき |
| --- | --- | --- |
| 物理 R/W 取得専用 SQL の接続設定・スキーマ・状態行 | 同じ DB とロックの物理同一性で、実 SQLite 検証と接続終了を通って許可された新世代。その後、正常観測2回 | immutable 側のみ正常でも固定通知を維持。物理同一性が同じ再オープンは証拠を引き継ぎ、別ファイルの成功は元の失敗の解除根拠に使わない。観測は物理 R/W SQL を発行しない |
| close、所有、ファイル ID、番兵等 | 従来の所有元・状態・指紋照合と正常観測の連続性 | 競合・未確認は解除を保留 |
| 最終 verify 直後の指紋が初めて示した STOP／番兵 | 同周期に肯定証拠を採用 | 読取失敗・不一致を理由に得た肯定証拠を捨てない。解除回数は進めない |
| 選択済み旧履歴の所有マーカー | 読取・同一性・close が正常 | 一次異常と close を共有ヘルパーで区別し、選択済み履歴の拒否まで持ち越す |

## Dots M02 の来歴

`pv-dev-baseline` はローカル参照 9c5b9bf9。再利用接続だけを追う処理は 383aba03／aaeeacea／0d49b74a で導入され、いずれも基点に含まれる。新規接続の HTTP 送信後・応答前 I/O を再試行可能な失敗として扱う経路と、共有側がその型で番兵を片付ける処理も基点に存在する。今回ここまで変更すると、基点の再試行と共有番兵の回復契約を変える。GET の冪等性と共有番兵の扱いに関する既存制約として判断を監督へ残す。今回の変更は新規 HTTPS の再試行条件を変えない。
