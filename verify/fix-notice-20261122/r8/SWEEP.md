# 第8回　資源の終了異常の棚卸し

基点 `1915480a`。Sol・Neon の全文を読了。各行では終了処理以前に確定した STOP、429、結果不明、拒否を優先する。終了異常の帰属は資源を確保した側で決める。

| ID | 資源と終了異常 | 取得・拒否への影響 | 非侵襲観測と確認方法 | 帰属 |
| --- | --- | --- | --- | --- |
| A01 | 稼働中ゲート SQLite R/W 接続、close | 開いた行の読み取り後であっても close が失敗したら送信前に拒否。既読 STOP は保持 | 取得と同じ既存ファイルの R/W 接続を、SQL・復旧・新規作成なしで開閉。失敗は unverified | DB の local／shared |
| A02 | 稼働中ゲート SQLite immutable、close | 取得は A01。既読行が STOP なら観測でも保持 | immutable と close を検査。健全な open の証明には両接続の終了成功が必要 | DB の local／shared |
| A03 | プロファイル SQLite immutable、履歴 SQLite immutable、close | 参照不明は保存異常。既読履歴 STOP は保持して転記 | 両側で共通の接続・終了境界。既読 STOP と終了異常は別証拠 | プロファイル local／選択済み履歴 shared |
| A04 | ロックファイル、番兵の R/W/readonly ハンドル、close | 拒否・結果不明・既読 STOP・429 を保持して異常併記 | 同 open モードで番兵と終了を確認。観測ではバイトロックを取得しない | ロックの local／shared |
| A05 | OS バイト unlock、プロセス内 RLock release | 実際に解放できたか不明なら拒否。旧履歴で明示 unlock 失敗でも handle close 成功により解放が確定する契約を維持 | 実際のロック取得／解除は観測しない。後続のファイル検査にない終了証拠を保持 | 資源を取得した local／shared |
| A06 | 所有マーカー／参照、番兵・DB ヘッダの read ハンドル、close | 検証不成立は保存異常 | 共通マーカー・検証を再実行。開閉失敗が続けば unverified | 検証対象の local／shared |
| A07 | shared intent ファイル、作成・close／親ディレクトリ権限ハンドル、close | 作成拒否は送信0、既記録は結果不明。失敗した途中の記録を保持 | 作成せず親の FILE_ADD_FILE を開閉。取得と観測の権限拒否を合成注入 | shared |
| A08 | 標準 OwnedHTTPS session の応答、接続、ソケット、登録、プール cleanup | 受信済み429は上限1と3の双方で即時停止し、保存異常を併記。成功後の終了不能は再試行不可 | 取得・DNS・ソケットを起動しない。終了不能をファイル側の健全な観測で解消しない | トランスポートを包むゲート |
| A09 | idle プール退役、候補ソケット廃棄、タイマー／フェンス | 所有プールの失効・再利用不可・中断を維持。後続送信の許可は与えない | 取得中プールに触れず、失効は R/W DB の状態と独立 | トランスポートを包むゲート |
| A10 | Draft トランスポート、入れ子 local/shared、旧履歴の外側 close | 内側の一次状態と外側の異常が逆方向のどちらでも分離される | 健全な反対側の観測では終了異常の固定通知を消さない | 失敗した側 |
| A11 | 初回セットアップの起動チケット、取消／拒否後の close | 取消・拒否／既読 STOP と終了異常を保持 | 起動チケットは観測から取得しない。未確定の初期化を許可に変えない | shared |
| A12 | POST の owned HTTPS／二重ゲート、終了異常 | 401/403 の永続 STOP を保持。終了異常付き結果を indeterminate とする | 通信を起動せず、ゲートの永続 STOP のみ観測 | 失敗したゲートまたはトランスポート |
| A13 | 最終指紋で新しい STOP・結果不明を検出 | 既存 GET の安全性は変わらない | 安定確認できた読み取り可能な STOP／結果不明を同じ周期で返す。競合時は解消を保留 | 指紋が変わった local／shared |

ロック・R/W 接続の観測は許可判定の代用にしない。ネットワーク資源の失効や明示 unlock は、既存ロックへの介入なしには再現できない。観測では共有可能な資源の開閉と、取得時に得た終了異常の証拠を組み合わせる。

## 試験と修正の対応

| 行 | 実装を通した注入または制御 |
| --- | --- |
| A01–A03 | local／shared の mode=rw close 拒否、immutable close 拒否、既読401と最終 profile close 拒否。SQL authorizer と実ファイルの内容・mtime で観測側の無変更を検証 |
| A04–A05・A10 | 外側 local の close／unlock と共有の結果不明、外側の選択履歴 close と内側 local の拒否。誤帰属した側が健全でも固定通知を保持 |
| A06–A07 | 共有マーカー read／close、intent write／close の同時異常。親の FILE_ADD_FILE 拒否、sidecar／来歴での Win32 21。送信0 |
| A08–A09 | 標準 HTTPS の local／shared／Draft 各経路で上限1／3と終了異常。idle 退役は TimeoutError、OSError、RuntimeError を注入。先行取得の数字と停止理由の表示を検証 |
| A11–A12 | 起動取消後のチケット close と、POST 401／403 の記録後の共有ロック close |
| A13 | 2回目／3回目の最終確認で401または結果不明を注入。読取後の local／shared のロック close・DBハンドル close・busy を6組追加し、既知の結果を保持 |

通信資源は、取得時に記録した終了異常を、その資源を検査できないファイルの観測で解消しない。通常の429上限到達と終了の確認不能による早期停止には別々の表示を使う。
