# 第10回 取得中止通知の解除条件

ベースは `3c3e7225`（第9回の実装 `e8c2039f` と同じ）。解除を許すのは現在の観測が一貫していて、停止元の検査に合格し、必要な選択証明を取得し、これが連続して2回確認できた場合。取得側のゲート判定に通知用の証明を使わない。

| 証明・入力 | リーダー／ゲート世代 | 合算・解除の条件 | 試験 |
| --- | --- | --- | --- |
| 保存済み選択の参照、参照先ファイル、プロファイル DB の同一性 | 現在の所有元と、現在の設定に接続されたリーダー | 現リーダーの拒否に必要な選択証明だけを、拒否を出した停止元の観測と照合。証明なし・不一致は保持 | M04、r6/r7 の stale-reader 試験 |
| 選択証明を伴う前リーダーの拒否 | 同じゲート上の旧リーダー、またはゲートも更新された旧世代 | 現世代に合算しない。旧拒否の通知は出せる。解除には現ゲートの安定した観測が必要 | M04、切替前後・遅延した拒否・選択を戻す条件 |
| 選択証明を伴わない拒否（Draft、共有・SQLite・所有確認等） | 全リーダー。設定に接続していない経路も含む | 選択条件を増やさない。現世代の選択条件を別の拒否で上書きしない。I/O と所有元の検査は維持 | M04 の証明なし拒否、M03、L01 |
| 前後のファイル指紋（ロック、DB の同一性・サイズ・時刻・内容、所有元、番兵、キャッシュ、R/W 検査）と最終照合 | 観測に使ったゲート。ローカル・共有・選択履歴 | 不一致・busy・拒否は解除に加算しない。後側の新規 STOP／結果不明は、照合失敗も記録して同じ観測で出す | M01、r5/r8 の照合試験 |
| R/W SQLite の open／close、接続設定、スキーマ・停止行 SQL | 各現ゲート。選択履歴は実取得と同じ immutable 検査 | open／close と SQL の両方が必要。物理 R/W の開閉では SQL を実行しない。SQL は同じ検査を immutable 接続で行う。継続異常は unverified | M03、r8/r9 の副作用・close 試験 |
| 観測開始後の拒否または現リーダー切替 | ポリシーの公開世代、ゲート／選択を共有する現リーダー世代 | 古い観測を適用しない。選択の切替では選択条件つきの確認回数をリセット。ゲートを交換したときは全ゲート通知の解除回数と停止元縮小の候補をリセット | M04、r4 の世代フェンス |
| 停止元 local／shared、永続 STOP の状態、未解消の共有 GET | 各対象ゲート。複数ゲートを観測する場合も対象単位 | 同一の永続 STOP は停止元集合を表示。縮小は2回一致。結果不明は共有の番兵確認を要求。違う停止元の選択や正常結果で解除しない | M01、r4/r5 の停止元試験 |
| 終了異常で保持された一次の拒否、追加の cleanup 情報 | 資源の所有元。リーダーの切替に依存しない | 型変換をまたいで cleanup の帰属を保持。再検証可能な保存異常は現ゲートの確認で解除 | L01、r7/r8 の帰属試験 |
| 連続観測数、期限、429 | 観測世代。同じ要求ポリシーの 429 ラッチ | 不整合は連続回数をリセット。未解消の監視を期限で止めない。429 は通知照合では解除しない | M01／M04、r6 期限、H01 の発行枠待ち |

R/W SQL は接続別の同期設定、スキーマ、停止行を取得と同じコードで確認する。immutable 接続のため書込み・回復・SQLite のロックを伴わない。書込み可能 VFS だけで発生する SQL 時の障害を再現するために観測で同 VFS に SQL は発行しない。物理 R/W の open／close と既存のファイル／ロック範囲検査は別に維持する。immutable R/W 経路の SQL が失敗した場合は unverified とし、読取専用の経路に切り替えて停止情報の診断を試みる。確定した停止行と確認済みの番兵は、その後のプロファイル読取や照合の失敗で捨てない。キャッシュと DB 行の不一致は unverified とする。
