## N1 の回帰試験

初回案内を閉じ、固定 640×400 とページズーム 200% の両方で、通常と併発を操作した。キーボードによる移動の直後に `activeElement`、ナビの可視状態と `aria-expanded`、要素中心の `elementFromPoint` を照合した。ナビ外の Esc はヘッダーと本文にフォーカスを置いたまま開閉ボタンを発火させ、実際のキー入力で確認した。

| 経路 | 修正前 `b267d04` | 修正後 |
| --- | --- | --- |
| 入口から Tab でナビ 10 項目を巡回 | 項目に順に到達。各中心が見える | 合格 |
| おすすめ → Tab | 「取得・更新」に移動したがナビが開いたまま。中心の最前面はナビ | 「取得・更新」のフォーカスを保ち、ナビが閉じる。ボタン中心が見える |
| そのまま Esc | ナビが開いたまま。ボタン中心が覆われる | 閉じたまま「取得・更新」のフォーカスを保つ |
| 先頭 → Shift+Tab で入口 → Shift+Tab でヘッダー | 移動先は正しいが、ヘッダーに出てもナビが開いたまま | ヘッダーに出たとき閉じ、移動先の中心が見える |
| ナビ項目・入口から Esc | 入口に戻り閉じる | 入口に戻り閉じる。入口の中心が見える |
| ナビを開いたままヘッダー・本文から Esc | 開いたまま、外のフォーカスが残る | 閉じて入口に戻る。入口の中心が見える |

同じ検査を修正前の Git オブジェクトと更新後の HTML に適用した。修正前は各条件 13/18、計 52/72、終了コード 1。修正後はダーク・ライトとも各条件 18/18、計 144/144、終了コード 0。[検証スクリプト](check_wireframe.py) · [修正前 JSON](before.json) · [修正後 JSON](after.json)

## H2 の比較実測

固定は Chromium のページズーム 100%・640×400 ビューポート（DPR 1）。ズームは 1280×800 のビューポートを Chromium のページズーム 200% にし、`innerWidth × innerHeight` が 640×400（DPR 2）であることを照合した。通常は短い DB 警告、併発は長文 DB 警告・取得停止・未解消の失敗 2 件。初回案内は閉鎖済み。カスタムランキングの一覧をスクロール先頭で測り、クリップ内に全体が収まった画像とキャプション込みのカードを数えた。学習の絞り込みはないため、各一覧条件から学習に移動して同じ合成画像と判定四択を測った。

| 測定条件 | 状態 | 絞り込み | 余白・画像を詰める案 画像／カード | 同 学習画像 CSS px | 警告要約案 画像／カード | 同 学習画像 CSS px | 四択（両案） |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| 固定 640×400 | 通常 | 畳む | 4／4 | 230.5×172.9 | 3／0 | 225.2×168.9 | 4/4 |
| 固定 640×400 | 通常 | 展開 | 4／4 | 230.5×172.9 | 0／0 | 225.2×168.9 | 4/4 |
| 固定 640×400 | 併発 | 畳む | 4／4 | 203.9×152.9 | 3／0 | 225.2×168.9 | 4/4 |
| 固定 640×400 | 併発 | 展開 | 4／0 | 203.9×152.9 | 0／0 | 225.2×168.9 | 4/4 |
| ページズーム 200% | 通常 | 畳む | 4／4 | 230.5×172.9 | 3／0 | 225.2×168.9 | 4/4 |
| ページズーム 200% | 通常 | 展開 | 4／4 | 230.5×172.9 | 0／0 | 225.2×168.9 | 4/4 |
| ページズーム 200% | 併発 | 畳む | 4／4 | 203.9×152.9 | 3／0 | 225.2×168.9 | 4/4 |
| ページズーム 200% | 併発 | 展開 | 4／0 | 203.9×152.9 | 0／0 | 225.2×168.9 | 4/4 |

小型化案は修正前の HTML に比較用 CSS を適用し、画像の縦横比を保って 3 列から 4 列にした。先頭画像の高さは 167.5 から 127.8 CSS px、一覧の左右余白は 12 から 8 CSS px。警告要約案を採用した。先頭画像のサイズを維持し、併発時は警告帯の高さが 48 から 28 CSS px になり、学習画像の可視高も 148.9 から 168.9 CSS px に増えた。保存先のルートと末尾、取得停止入口、未解消件数は常設した。併発で要約が 1 行に収まり、詳細を Enter で開くと完全な保存先と警告全文が見え、Esc で入口に戻ることを確認した。展開後は絞り込みと一覧を末尾までスクロールし、畳むボタンの中心が可視で、`+N` と畳む操作がキーで使えることを確認した。

**Dots の値との差。** 同じ Windows Chromium では修正前から両モードの枚数が一致し、先頭画像寸法の差はサブピクセルの丸めだった。併発・畳みの一覧高は 179.5、先頭画像高は約 167.5、学習画像は約 198.5×148.9 CSS px。Dots の固定条件は一覧高 132、先頭画像高約 163、学習画像約 171.9×128.9。画像 0 枚の直接原因は、Dots の一覧高が先頭画像より約 31 CSS px 低いこと。Chrome ページズームの有無だけを切り替えても、この差は再現しなかった。外部側の警告帯・ヘッダー・ツールバーの矩形、実フォント、スクロールバー幅の記録を取得できていないため、48 CSS px の差を生んだ外部側の条件は未特定。独立再確認に、更新後の両条件と同じ矩形の採取を引き継ぐ。[修正前と比較案の JSON](before.json) · [採用案の JSON](after.json)

## 既存回帰と引き継ぎ

- 隔離 Chromium で H1 の 4 検査、同じ作品の並べ替えとタブ往復、失敗の確認済みと解消、取得停止の回復と設定 OFF の模擬遷移を再実行した。100% の 3 サイズと 125% の通常・併発 × 畳む・展開 × 2 テーマの 32 条件を再計測し、既定の学習画像下限を持つ 3 サイズは下限以上だった。ブラウザー外部要求とページエラーは各 0 件。
- 製品の全体 pytest は指定 venv の `-B -m pytest -p required_network_guard -k "not dpapi"` で実行し、4,496 passed・2 failed・13 skipped・3 deselected（23 分 27 秒）だった。テスト時の `src` と `tests` は `b267d04` と一致。キューの試験 1 件の失敗と 10 件のスキップには、隔離した `LOCALAPPDATA` を Playwright が既定の探索先にする影響があった。導入済み Chromium の場所を指定して該当 4 ファイルを再実行し、35 件が通った。設定画面の試験も単独再実行で 1 件が通った。全体実行内での設定画面失敗の原因は未特定。同一条件の全体一括合格は未取得で、残る 3 スキップは Windows のシンボリックリンク作成条件。[pytest 出力の要約](pytest-summary.txt)
- 監督にこのコミットと実測を渡して独立判定を受ける。M1 は実機担当による改修前 Flet／改修前 NiceGUI の同条件測定後、監督が合格下限を決める。A17 の製品合否と 200% の学習画像下限は製品比較で判定する。
