## 発見と次の作業

- 200% では、開閉式ナビを追加した直後も長文併発で完全表示は 0 枚だった。先頭画像に対する一覧の高さを確認し、ヘッダーの折り返しとツールバー間隔を調整した。640 CSS px 以下の発生・解消通知は読み上げで維持し、画面上は件数・内訳を常設する。元の第 2 回ワイヤーフレームで 76.9×57.7 CSS px だった学習画像は 198.5×148.9 CSS px になった。展開時の完全表示と、キャプションまで含めたカードは未達。
- 展開時にも完全表示が必要なら、赤い警告帯に本番 DB の使用と保存先を常時表示し、補足の長文を同じ帯から展開する案を比較する。取得停止の入口と失敗件数は常設する。展開後の全文の到達性と、得られる高さは追加計測が必要。
- この候補の証拠を監督へ返し、原受入の独立判定を受ける。製品工程では、同倍率・同条件の Flet 並置と改修前 NiceGUI を測り、125% の必須 2 条件の下限を決める。200% は面積率を参考に、A11、完全表示枚数、学習画像の下限と四択を判定する。[設計書](../../../docs/design/UI_NAV_RESTRUCTURE_20261122.md) · [監査仕様](../../../docs/UIUX_AUDIT_SPEC_20261122.md)
