# r5 ビューア閉鎖と一覧再描画の棚卸し

土台は ui-integ の e95a4b14。対象は Dots UIINTEG-R4 の R4-M01 と R4-L01。ライブラリの保留更新は、ブックマーク投影（バックグラウンド取込）、ローカル再読込、外部ライブラリの借用終了から発生する。カードの再描画は通常の outbox、ビューア閉鎖と次フレームの復帰は ArtworkPage の順序付き配信。ブラウザーの DOM 監視は両者の間でも走る。

| 変化の順序 | 元のカードが戻る場合 | 元のカードが消える場合 | 隔離ブラウザーの試験 |
| --- | --- | --- | --- |
| 一覧の更新が先 | 古いノードを破棄し、同じ作品の新ノードへ | 近傍／見出し等の有効な代替位置を保持 | ビューア表示中に一覧を更新し、閉鎖を後で送る |
| ビューアの閉鎖が先 | いったん古いカードまたは代替位置へ移る。次フレームの復帰で新ノードへ | 消えたカードの代わりに安全な位置へ移る | 閉鎖を先に観測し、復帰フレームまでの間に一覧を更新 |
| 一覧の更新と閉鎖を同じ処理から送る | 更新と閉鎖の間に代替位置を置いても、新ノードへ復帰 | 安全な位置を維持 | 同じサーバー処理から一覧の更新、ビューアの閉鎖を送る |

いずれも別の有効な要素へユーザーが移動した後なら復帰で上書きしない。通常の閉鎖、ページ矢印の無効化、画面を切り替えた後の無効な世代は既存回帰で確認する。

| Tab 順 | 従来 | r5 の検証 |
| --- | --- | --- |
| ダウンロード詳細内のフォーム | すべてを一枠として記録 | モード、検索、作者入力、フォロー操作、表示行の中の順序を個々に照合 |
| ランキングとライブラリの日付選択 | カレンダー全体が一枠 | 見出し・月年ナビゲーション・選択可能な日付・末尾の操作を画面仕様の順に照合 |
| 履歴行の複数ボタン | 履歴行を一枠として記録 | 合成履歴の作品ボタンと外部ページ操作を個々に照合 |

M03 と M04 は fix-notice の取り込み後。通知表示と監視、送信、取得停止ゲート、429 即停止は今回の変更範囲外。

## 実装後の確認

制御したブラウザー試験では、実の LibraryView の保留更新と ArtworkViewer の閉鎖後 RAF を用いた。カードの「更新先」は閉鎖までにフィルターで一度消して再生成。「閉鎖先」は閉鎖を観測してから、保留中の復帰フレームまでに消失・再生成。「同じ処理」は同じサーバーイベントから一覧更新と閉鎖を送った。どの順序でも同じ元カードを見失ったケースと、実 Tab で別要素へ移ったケースを測った。カードが再生成されなければ、有効だった代替位置をそのまま維持した。

| 条件 | 修正前 | 修正後 |
| --- | --- | --- |
| 再生成あり、ユーザー移動なし（3順序） | 3/3 失敗 | 3/3 合格 |
| 再生成なし、ユーザー移動なし（3順序） | 3/3 合格 | 3/3 合格 |
| 実 Tab で別要素へ移動（3順序×再生成有無） | 6/6 合格 | 6/6 合格 |
| 詳細フォームとカレンダーで内部順を意図的に入れ替え（各1） | 旧試験がどちらも見逃す | 2/2 検出 |
| 日付選択3経路、詳細フォーム、履歴の正常順 | 旧試験のグループ測定で5/5合格 | 個々の操作を照合し5/5合格 |

試験調整の記録。最初のユーザー移動ケースは、マウスクリックが Quasar の内部要素に着地して期待したボタン本体を確認できなかったため、実 Tab と移動前後の要素の比較に変更した。最初の内部順の試験は Quasar のラベルが入れ子のため要素取得に失敗し、同じ期待順のままセレクターを修正した。
