対象は ui-integ の 9d39113。表示・削除・無効化・再描画を44ファイル292行で静的確認した。経路別に、現状の復帰先と試験を対応づけた。

| 経路 | 現状の復帰先と穴 | 隔離試験 |
| --- | --- | --- |

## 共通化と検証結果

フォーカス取得時に要素、明示起点、近傍の候補と祖先を記録する。DOM の削除・非表示・無効化で、元の要素が使えず、後続の有効なフォーカスも無い場合だけ復帰。復帰順は有効な明示起点、同じ画面／モーダルの近傍、画面の見出し。クリックによる明示閉鎖、Quasar ダイアログの復帰、非同期読込の個別起点も同じ処理を利用する。既存の各画面の操作先指定と、表示世代、タブ有効性、範囲の制約を保持した。

| 確認した共通経路 | 実ブラウザー試験 |
| --- | --- |
| ヘッダーの明示閉鎖、明細4→3、重要通知が全消失 | DemoShell 上でメインの起点を必須とした test_shell_request_focus_and_live_roles_r3。取得通知の既存設定・プロフィール配置も回帰試験 |
| 学習帯の期限切れ、無効化、一覧の再描画、近傍を全削除、別のフォーカスを保持 | test_application_focus_loss_fallback_r3。実の LearningToast の期限切れ、領域削除とロール付き見出しを使用 |
| 全停止位置の巡回、起点の復帰 | walk_focus は実 DOM の停止位置を毎回照合。止まり続ける挙動は専用の失敗注入で検出。小説・うごイラは実行ボタンと非同期データ読み込み、別フォーカス、閉鎖後の元の行を検証 |
| ロール設定、固定停止の確認済みと待機、秒更新、自動で消える完了 | 共通通知の通常／置換経路、実 Shell の停止・待機混在。秒更新でライブ側の子 DOM が変化しないことを確認 |
| 学習の起動時失敗 | DiscoveryLearningService の候補キャッシュを隔離し、起動初期化の I/O エラーを合成。LearningView が表示した重要通知からフォーカスが復帰 |

実画面の代表経路に加え、共通処理を通る削除・無効化・時間経過・フォーカス移動済みを試験した。個別画面は静的棚卸しと既存試験を照合した。実機の支援技術の読み上げは監督側の確認に残る。

## 全体試験で見つかったビューアの復帰順

ページ送りで先頭・末尾に着いたときは、フォーカス中のボタンが無効になる一方でビューアは開いたまま。行の起点へ戻すのはビューアの閉鎖時とし、表示中の操作では反対側のページ送りボタン、次いでビューアの閉じるボタンを候補にする。ビューアの個別フォーカス監視を除き、共通処理がこの候補を評価する。ブックマークの実画面で、端に達する両方向のキー操作と Escape の起点復帰を既存試験で照合した。 [全体の失敗](PYTEST_FULL.txt) · [差分の再検証](VIEWER_RECHECK.txt)
