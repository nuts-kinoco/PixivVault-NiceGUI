# GPU 作業 4 再レビュー対応

`gpu-shadow` に `pv-dev-baseline` の `7c57e15` を統合した点は `d6a9f5e`。学習画面と通信棚卸しは Git の自動統合が成立した。交差箇所は学習画面の既存見た目と画像フックを確認した。製品コード候補は `7ad3e9261629d9af81f87faf0bbdac1e6a9a3e74`。

作業 4 の隔離受入を確認した。関連 160 件と全体 4,334 件が合格し、差分のデータ保全と並行処理を Sol が独立読取りで確認した。製品受入、実機、実 GPU、補正適用とサービス配線は後続の判定範囲。

## Neon 指摘への対応

| 指摘 | 修正と確認 |
| --- | --- |
| #1 失効と DB 退役 | 制御 epoch と SQLite の単調な世代番号を一組で照合。両制御レコードの置換失敗、通常 Undo の取得交差、DB 退役直後の戻り値、コミット後の保留行回収を試験した。 |
| #2 明示 CUDA 読込 OOM | 一時的なメモリ不足だけを解放対象へ登録して、同じモデルと設定で再試行可能にした。恒久エラーは失敗ラッチを維持する。 |
| #3 `None` の判定 | `null` 判定は未判定として除外し、明示の空判定による既存の弱ラベルは維持する。理由なしの `hate` は未確定で、同じリビジョンの確定理由で補える。評価器は作品ごとに未判定、理由なし、矛盾、無効、ベクトルなしを集計する。 |
| #4–6 GPU の停止と再開 | 個別停止は当該 GPU 待機だけを取消し、共有停止は戻る前にストアを失効する。待機している類似ワーカーへの明示再開を新しい GPU 世代に置き換える。 |
| #7 学習 FIFO | 判定スナップショットと世代失効を境界に残し、イベントの `synchronous=FULL` 追記を有限の別キューへ移した。故障・欠落を集計し、未記録のまま終了した場合はドレインでエラーを返す。 |
| #8 順位の重複 | 候補取得後に、消費側の最終順位だけを決めて記録する。 |
| #9 実ピンと恒久比較 | `LearningView._start_prefetch()`、同一ピンの OFF→ON→OFF、モック CUDA 稼働中の GET 列一致、表示完了時の LRU 不変を試験した。192 ケースの生成条件を恒久テストにし、`a466487` の順位・枠を基準にした。 |
| #10–13 細部 | I/O エラーだけが失効の代替経路へ進む。表示時の順位は残り候補内の尺度とし、セッション通算位置は別項目にした。ログは経路名と例外クラスで本文を出さない。サムネイルは変種の観測だけ行い、CUDA 推論・埋め込み挿入を省く。 |

Sol の独立読取りで、削除後の保留イベント・画像の再投入、DB 退役と戻り値の競合、通常 Undo がフェンス取得をまたぐ競合を追加で確認した。既に受理した画像・イベントに削除専用 epoch を付け、通常失効で取得中の一枚が古くなった場合は、その一枚だけを破棄する。恒久障害に対する停止と区別する。
