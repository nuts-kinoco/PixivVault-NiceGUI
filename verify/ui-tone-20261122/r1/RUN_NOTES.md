# UI トンマナ監査 第1回 実行記録

対象は `ui-tone-audit` の起点 `0ff4d7572221485833fa4438628256e4a9c46fed`。元 Flet は `3ac3aa0d47a64785251593bcb09bb2d5f6df374b` の追跡ソースを隔離領域に展開した。設定や保管庫を含む製品データを持ち込まず、ローカルの合成データで両画面を開いた。

## 証拠

- [トーン一覧](TONE_MATRIX.md) に条件別の行と上位10件を掲載。各条件の画面フォルダの `port.json` が NiceGUI の DOM、`original.json` が Chromium のアクセシビリティ DOM と実行中 Flet コントロールの宣言値。`paired.png` は左が Flet、右が NiceGUI。
- [撮影台帳](summary.json) に候補、条件、全画像、接続ガードの記録を収録。ブラウザが拒否した元の Rive CDN へのリクエストは台帳に記録した。NiceGUI 側の `transport` 記録はローカルの合成応答への呼び出し。
- [プロセス記録](lifecycle.json) と [終了後の再確認](process-postflight.json) に、撮影用 Chromium とサーバーの終了を記録。`S:\Work\_tmp\PV\codex-ui-tone` の試写、検証ログ、ブラウザプロファイル、合成データベースは監督の片付け対象。

## 撮影中に見つかったこと

- 学習の正常表示では、既存 P5 の待機対象だった失敗カードが出ない。実際の学習ルートの表示を待ち、合成画像がブラウザでデコードされた通常ケースを撮影した。
- 実通信の代用が例外で終わると、合成の中断GET案内が通常画面に出た。通常撮影にはローカルで完結する合成応答を使い、永続停止と中断GETは専用ケースで撮影し直した。
- Flet 宣言値の固定応答ファイルが Windows の共有違反で更新できなかった。応答ファイルを要求ごとに分け、欠けた条件だけ再撮影した。
- 試写のプロセス照合で再利用された PID が混入した。追跡に生成時刻を加え、最終確認では起動専用のプロフィールパスとサーバー引数でも照合した。

製品デザインの同等判定には、元の表示と並置画像を基にした目視判断が残る。Flet の実描画スクロール高、カード影や既定フォントの最終解決値は DOM からは取得できない。ライト、長文、Native の実機画面は今回の条件に含めていない。
