## 指摘と対応

| 指摘 | 真偽と対応 |
|---|---|
| Medium-1 | 真。9生成経路すべてを応答後の実 Outbox で調べると、各63要素中10要素が二重登録。4経路は未オープンのビューア向け JS も1～2件。初期 props・イベントを結線してから bind し、未使用の閉じる処理を省いた。修正後は HTML 前／後とも各63要素で重複・不要 JS とも0。 [全数確認](SWEEP.md) |
| Medium-2 | 真。ブラウザーの表示失敗で GIF の両参照が残り、別 app で同じ URL が200。サービス閉鎖後も200だった。登録を app スコープに移し、失敗・検索での選択解除・再試行・交代・削除で失効。閉鎖後503、別 app は404。既存の PNG と同様に HEAD に対応。 |
| Medium-3 | 真。HTTP と遅延生成を実装の経路で試験し、構築・配信箇所が増えたら見直しを要求する検査を追加。タグは非空の props をセットしてから空を検証。空クリアを無効化すると新テストが失敗する。 |
| Low-1 | 真。小文字 UUIDv4 hex と bytes を検証し、GET と HEAD の応答ヘッダーを検査。 |
| Low-2 | 真。削除済み client への退役送信を抑止。単一ルート制約を Python と Vue で明示。NiceGUI 3.18 の通常の client 削除順で生じる退役エントリは停止した Outbox に残り、通信しない。 |
| Low-3 | 基点の所見。容量キャッシュの遅着で表示が巻き戻る可能性、イベントループ外でデバウンスを呼ぶ境界、非表示操作の完了通知が切替先に表示される可能性。今回の調査はコード照合まで。基点の境界を維持した。 |
