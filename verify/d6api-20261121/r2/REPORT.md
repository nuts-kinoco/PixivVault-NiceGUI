| 指摘 | 対応と確認 |
| --- | --- |
| M1 | アイドル30秒で TLS ソケットを廃棄。借り出し時も期限、TLS の pending、ソケット可読性を確認する。FIN と未要求データを実 TLS で観測し、新規接続で1回だけ送信された。再利用接続が送信開始後に切断した場合は、上位設定が再試行を許しても自動再送しない。応答を受ける前に切断すると相手側の受領を確定できず、同一操作を再送するとゲートの意図との対応が曖昧になる。次の明示 GET はゲートを通過して新規接続する。 |
| M2 | `urllib` の `do_open` と同じ `title()` 正規化。新規・再利用の両方でサーバーが受け取った User-Agent / Accept-Language / Accept-Encoding を基準経路と照合した。 |
| M3 | 並行2件が各自の TLS 接続を使いアイドルに1本だけ戻すこと、2層ゲートのローカル停止・共有停止・成否不明・致命ステータス、実 Cookie リーダーでの合成 Cookie ローテーションとアカウント切替を検証した。gzip は受信上限、展開上限、chunked、CRC破損、重複、未要求、非200を確認した。信頼されない証明書・ホスト名不一致では HTTP 送信0件。 |
| L1 | 本文 `read1()` の前に残り期限でソケットのタイムアウトを更新する。遅いヘッダーの後に本文を止め、設定された残りタイムアウトと読み取り終了、ゲート解放を検証した。Windows では shutdown 時点にすでに待機中の読み取りの即時復帰までは保証しない。 |
| L2 | HTTPConnection が内部に保持する完了応答からヘッダー・理由・URL を除去する。呼び出し結果への Set-Cookie の引き渡しは除去前に行う。実 TLS の応答を観察し、Cookie 更新と接続再利用を確認した。 |
| L3 | 既定 CA と証明書・ホスト名検証を維持したうえで、SSLContext を単調時計の5分区間で再生成する。旧区間のアイドル接続は借り出さず、新規 TLS で再検証する。進行中の要求には既存の期限が適用される。 |
| L4 | アイドル接続の破棄をプール状態のロック外へ移した。破棄中も状態は取得可能で、次の借り出しは破棄の確認または失敗の記録まで待つ。 |

元環境の urllib3 にある借り出し時の切断確認を参考にした。公開されている Cloudflare のクライアント側 HTTP/1.1 の既定は400秒だが、Pixiv や途中経路の切断時刻はこの回で計測していない。30秒は短い連続操作での再利用を維持し、長い無通信後は新規 TLS とするローカル方針。HTTP/1.1 では相手の切断と送信開始が競合し得る。 [urllib3 接続プール](https://github.com/urllib3/urllib3/blob/2.6.2/src/urllib3/connectionpool.py) [Cloudflare TCP 接続](https://developers.cloudflare.com/fundamentals/reference/tcp-connections/) [RFC 9112](https://www.rfc-editor.org/rfc/rfc9112.html#section-9.5)

30秒の本設定を使った別のループバック TLS 試行では、2件目の送信前にサーバー側でアイドル接続の終了を30.0005秒で観測した。その後の明示 GET は別の TLS 接続を使った。 [30秒の実測](idle-expiry-30s.json)

## 回帰と逸脱

- 基点で M1・M2・L1〜L4 の6件が対応する仕様のアサーションで失敗、18件が通過。再利用切断に上位の再試行設定を組み合わせた1件も、修正前に再試行へ入って失敗した。最終の重点回帰131件合格、追加25件。通信棚卸し302箇所、未分類0。 [基点の失敗](red-verified.log) [再送の失敗](red-replay.log) [最終重点回帰](green-final.log) [棚卸し](network.json)
- 初期のテストでは、TLS フィクスチャと観測用パッチの解除順が試験 CA を次の試行へ持ち越した。観測パッチをフィクスチャ内で解除し、合成プロファイルのアカウント切替も専用資格情報ディレクトリへ合わせてから基点を取り直した。 [初期ログ](red.log) [取り直した基点](red-verified.log)
- 再送の仕様差を確認した時点で、修正前の全体試験の自分のプロセスツリーだけを終了した。最終候補を指定のネットワークガード、S: を起点とする既定の pytest 一時パスで別に実行した。 [終了記録](pre-replay-canceled.log) [全体試験](full-final.log)
- 最終全体試験は `-p required_network_guard -p no:cacheprovider -k "not dpapi"` で **3,997件合格、失敗・エラー0、3件スキップ、3件除外**。スキップは Windows のシンボリックリンク作成権限。長パス試験は合格。所要時間23分24秒。 [全体試験](full-final.log)
- 起動したプロセスの残存0。実 API は0 GET。変更ソースと証拠の資格情報パターン検査は合成テスト入力1件のみ。 [残存確認](process-check.json) [パターン検査](credential-patterns.json)
- ゲート・認証・Cookie・並行処理の受入判定には本人の独立検証が残る。
