## テスト

- 初回 red はツール未実装で 4 エラー。レビュー後の追加 red は 3 失敗、その後にロックの 1 失敗、コールド試行数の 1 失敗をそれぞれ再現。
- 最終 green は G0 7 件、P6 通信棚卸し 7 件が通過。新しい通信経路を検出せず `p6_network_review.json` の差分なし。
- 全体は指定 Python で `-B -m pytest -p required_network_guard -k "not dpapi"`、`PYTHONIOENCODING` なし、S: 上の `src;tests` と長い `--basetemp` で完走。4,100 通過、3 失敗、3 スキップ、3 除外、50 分 48 秒。失敗は一括選択 20,000 件と、Windows 共有遅延下での既存台帳の `active-generations.json`・`active-generations.head` の 2 ケース。既存の実装と試験にコミット差分はなく、独立静的確認でも G0 の呼び出しはない。
- 同条件の初回部分再実行は 2 通過、`active-generations.json` のみ失敗。冷読取りとウォーム読取りの直後に書込み子プロセスが既に終了していた。観測だけ追加した再実行では 3 通過。一括選択は 0.507 秒、400 チップ。Windows 共有の冷読取りは 3.168／1.589 秒。全体実行の失敗結果はそのまま。原証拠は `pytest-full.log`、`pytest-repro.log`、`pytest-repro-diagnostics.json`。
- 診断で既存の冷読取りの前に 6 秒の待ちを追加すると、`active-generations.json` で子が WinError 5 を返し、初回再実行と同じ「子が既に終了」の失敗を再現。書き換えリトライの既定 5 秒に対して読取り側の処理時間が越える経路を確認した。`active-generations.head` は同診断で floor ファイルのポーリング中に PermissionError になった。全体実行の各失敗時の例外・一括選択の実測値は取得できていない。両機構は既存の保存・読取り経路の担当へ渡す。原証拠は `windows-sharing-deadline-probe.json` と同名の `.log`。

## 逸脱と次の作業

- ORT のメタデータは `style_embedding=[1,1024]`。CPU 上で同じ前処理形状の異なる合成画像 2 枚と、保存画像 2 枚をそれぞれまとめて実行すると、絵柄は `[2,1024]`、バックボーンは `[2,677,1024]`／`[2,709,1024]` を返した。両出力の各行は独立した単枚推論の結果と最大絶対差 0 で一致した。モデルそのものがバッチ不可という設計 §1 の前提は実測により更新が必要。現行の `EgaraInference.infer` と G0 の性能計測は単枚単位を使用。原証拠は `batch-distinct.json` と `batch-distinct-native.log`。
- 独立 Sol 監査で共有リースの判定から更新までの競合、同じ owner での上書き、所有交代時の解放競合を再現。G0 の通常起動を Windows のロックで直列化し、子の実プロセス系統・所有 PID・期限・解放後の読戻しを確認するよう変更した。共有リース側は監督の所有範囲。ワーカーの期限監視は Python スレッドで動くため、ネイティブ呼び出し中の停止と解放は実 GPU で別途確認する。
- 本番プロファイル、実 Cookie、実 Pixiv、ポート 22386 は試験経路から除外。全実行の終了後に G0 起動プロセス 0、G0 リース残存なしを照合。原証拠は `process-check.json`。
- 次の承認済み作業は、G0 計測の独立判定にこの証拠を渡し、次のフェーズ 1 の担当へ絵柄の原画優先・単枚 API・リース要求値 2.5 GiB を引き継ぐこと。共有リース競合と 3 件の既存試験失敗は監督へ戻す。試験生成物・隔離環境の削除候補と証拠の保持先は `cleanup-inventory.json`。削除実行は監督の担当。

初回計測 `13090`、CPU-only 再確認 `27451`、全体 pytest `40157`、最終コミットの CUDA 再試行と CPU 照合 `36018` はすべて結果回収済み。
